= ADR-004: The token-stream interior lexer and the dialect grammar seams
:navtitle: ADR-004 Token lexer & seams

*Status:* Accepted. *Date:* 2026-06-01. Records the token-stream lexer (commit `85b2e0d`, Phase 3)
and the `parseHead` seam (commit `72a3090`, Phase D).

== Context

Originally each dialect carried its own string-based interior grammar (built on `purescript-parsing`).
To let several dialects share *one* parser while keeping the core meaning-free (ADR-001, ADR-003), the
tag interior needed a shared, meaning-free tokenization with a single, narrow seam where a dialect
plugs in its expression grammar.

== Decision

. *Keep the structural scanner; add an interior tokenizer.* `FlatBars.Lexer` (perf-tuned) still
  delimits tags into raw interior strings. A *new*, meaning-free interior tokenizer
  `FlatBars.Token.tokenizeInterior :: Int -> String -> Either ParseError (Array PosToken)` lexes that
  interior into `TIdent`/`TStr`/`TNum`/`TLParen`/`TRParen`/`TOp`.

. *Operators are lexed, not interpreted.* `pass:[& | ! < > == != <= >=]` are matched longest-first and
  given *no* meaning. `=` is an identifier-continuation char (so `key=value` is one `TIdent`), but
  `==` at a token boundary is the operator. Idents include `_ - . @ / + * ?` and `[bracket]` segments;
  they exclude `pass:[& | ! < >]` (those are ops).

. *Two seams on `ParseOptions`.* `parseExpr :: ExprParser` parses output/argument interiors;
  `parseHead :: ExprParser` parses block-open heads (added in Phase D for bare-infix block conditions
  like `pass:[{{#if a == b}}]`). The default grammar is the shared prefix grammar (`FlatBars.Expr`);
  MaxBars swaps a precedence-climbing grammar through the *same* seams (`Parser.purs:57`).

. *Two surface affordances that (ab)use operator chars, handled meaning-free in core.* (a) The partial
  sigil `>` — a *leading* `TOp ">"` is remapped to `TIdent ">"` in `Parser.partialHead`, so
  `pass:[{{> name …}}]` reads as an application headed by `>`. (This remap serves the partial
  *reference* only; the `pass:[{{#>name}}]` partial *block* is a first-class `PartialBlock` opener/sigil,
  not a `partialHead`-remapped section.) (b) Block-param bars `as |a b|` — the
  shared prefix grammar's `pArgs` accepts a bare `TOp "|"` as a nullary `App "|" []` atom. Core
  attaches no meaning; FullBars' `Surface` strips/splits them.

[NOTE]
====
*Two orthogonal extension axes — do not conflate them.* A dialect customizes the core along *two*
independent axes, and only one of them is the grammar seam:

* *Axis A — the grammar seam:* `parseExpr`/`parseHead`, how a dialect parses a tag *interior*. Adding
  a *third* grammar seam is the smell flagged in <<watch>>.
* *Axis B — the shape gate:* which *tag shapes* a dialect admits — `ParseOptions.extras` (ADR-001 §3)
  and the gated MinBars sigils (xref:adr-0007-minbars.adoc[]). Growing axis B (more gated sigils) is
  expected and fine.

MinBars grows axis B, not axis A; it is *not* the forbidden third grammar seam.
====

== Amendment (2026-06-04): one tokenizer — `RawTok` carries its interior

The structural scan and the interior tokenizer are composed in *one* place:
`tokenizeTemplate` now takes the interior `LexOptions` and populates each
expression-bearing `RawTok`'s interior at scan time. The interior travels *on the
token* — `RawTok`'s `ROutput`/`RAmp`/`ROpen`/`RClose`/`RSep` (and `RRaw`'s head)
carry an `Interior = Either ParseError (Array PosToken)` field — so *both* the
parser (`buildFromTokens`/`parseRecovering`) and the editor highlighter
(`FlatBars.Highlight.tokenizeSpans`) read the pre-lexed interior directly off the
token. Previously each consumer composed the two primitives independently
(structural scan, then a per-tag `tokenizeInterior` re-lex), so the interior
tokenizer ran once *per consumer* with no shared guarantee they agreed.

Nothing in the decision above changes: the interior tokenizer, its meaning-free
operator lexing, and the two grammar seams are exactly as specified — the seam is
still `Array PosToken -> Either ParseError Expr`, fed the same tokens; and
`tokenizeTemplate` stays meaning-free (`LexOptions` governs only the interior
token lexing, never the structural shape). `tokenizeInterior` runs once, at scan;
`outputExpr`/`headed`/`headedRecovering` take the pre-lexed `Interior` (the
blank-interior guard `trim s == ""` is exactly `Right []`), so the parser no
longer re-lexes. The interior is kept as the *deferred* `Either` (not flattened)
so a malformed interior rides inside its tag and never breaks the structural scan
(preserving ADR-023 recovery). The one dialect that *mutates* an interior string
after the scan — MinBars' Mustache standalone/partial-indent pass — re-tokenizes
those tags in lockstep, so their carried interior is never stale. The change is
byte-identical end to end (`test:compile` 300/300; the highlight golden unchanged).

== Consequences

* *Pro:* `purescript-parsing` is gone; three dialects share one parser; the dialect seam is a single,
  testable function type (`Array PosToken -> Either ParseError Expr`).
* *Con:* core knows about *surface-shaped* affordances (the partial-`>` remap, the block-param `|`),
  even though it assigns them no meaning — these regressed the partial/block-param tests until added,
  because the old per-dialect string grammars treated `pass:[> | < ! =]` as ident chars. Point-free
  mutually-recursive grammar bindings trip PureScript's `CycleInDeclaration` — eta-expand them.

[#watch]
== Watch

A *third* grammar seam (axis A) would break the "two seams" framing and signals the dialect-grammar
interface is leaking; revisit rather than accrete. This is distinct from growing the *shape* axis
(axis B) — more gated sigils — which is expected.

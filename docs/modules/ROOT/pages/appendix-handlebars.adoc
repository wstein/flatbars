= Appendix A — Handlebars.js → BareBars, with no gaps
:navtitle: A. Handlebars mapping
:toc: macro
:toclevels: 3

This appendix is the *contract*: every {hb} concept must have a defined BareBars equivalent, with no
gaps. Each entry gives the {hbs} form, the *BareBars Surface* spelling (what a template author
writes), and the *core* skeleton it desugars to (what the parser produces and the engine walks).
Surface rules are in xref:surface.adoc[]; engine helpers in xref:prelude.adoc[].

A concept maps in exactly one of these ways, marked throughout:

[horizontal]
[CORE]:: a first-class core skeleton construct.
[SURFACE]:: a pure syntactic rewrite to the core.
[ENGINE]:: meaning assigned by the Phase-2 walk — a helper, a clause name, or a validation rule. Not built in.
[HOST]:: an engine/assembly choice, not template syntax.
[DROPPED]:: deliberately not provided — with the replacement stated.

[NOTE]
====
*Parenthesis convention.* Top-level expressions inside `pass:[{{{ }}}]` carry no wrapping parens (a
top-level `Expr` needs no grouping). Parentheses appear only around a *nested* application in
argument position — `(lookup …)`, `(parent)`, `(dict …)`, `(index)`. See xref:grammar.adoc[] §2.2.
====

toc::[]

[#expressions]
== A.1 Expressions, escaping & paths

[cols="2,2,3,1",options="header"]
|===
|Handlebars |BareBars Surface |Core |Kind

|`pass:[{{x}}]` |`pass:[{{x}}]` |`pass:[{{{ esc_html (lookup this "x") }}}]` |SURFACE
|`pass:[{{{x}}}]` |`pass:[{{{x}}}]` |`pass:[{{{ lookup this "x" }}}]` |SURFACE
|`pass:[{{a.b.c}}]` |same |`pass:[{{{ esc_html (lookup this "a" "b" "c") }}}]` |SURFACE
|`pass:[{{a.[1]}}]` / `pass:[{{a.1}}]` |same |`pass:[{{{ esc_html (lookup this "a" 1) }}}]` |SURFACE
|`pass:[{{a.[home town]}}]` |same |`pass:[{{{ esc_html (lookup this "a" "home town") }}}]` |SURFACE
|`pass:[{{a/b}}]` (legacy slash) |`pass:[{{a.b}}]` |`pass:[{{{ esc_html (lookup this "a" "b") }}}]` |SURFACE
|`pass:[{{this}}]` / `pass:[{{.}}]` |`pass:[{{this}}]` |`pass:[{{{ esc_html this }}}]` |SURFACE
|`pass:[{{this.a}}]` / `pass:[{{./a}}]` |`pass:[{{this.a}}]` |`pass:[{{{ esc_html (lookup this "a") }}}]` |SURFACE
|`pass:[{{../a}}]` |`pass:[{{../a}}]` |`pass:[{{{ esc_html (lookup (parent) "a") }}}]` |SURFACE
|`pass:[{{../../a}}]` |same |`pass:[{{{ esc_html (lookup (parent (parent)) "a") }}}]` |SURFACE
|a helper returning HTML, e.g. `pass:[{{price}}]` |use `safe` in the helper |`pass:[{{{ price }}}]` |ENGINE
|===

*Escaping model.* {hbs} escapes `pass:[{{ }}]` and trusts `pass:[{{{ }}}]`/`SafeString`. BareBars makes
both explicit: `pass:[{{ }}]` is the *only* thing that introduces `esc_html`; `esc_html` returns
`VSafe` so re-escaping is a no-op; `safe`/`VSafe` is the `SafeString` analogue. See
xref:evaluation.adoc[] §3.7. The escaped set is `&`, `<`, `>`, `"`, `'`, matching {hb}.

*Why bare names differ between layers.* In Surface, `foo` is a *field* (`lookup this "foo"`). In the
core, `pass:[{{{foo}}}]` is a *helper call*. Authors write Surface and think in data; the desugarer
and engine work in the core. This is the single most important thing to internalise here.

[#helpers]
== A.2 Helpers, arguments & subexpressions

[cols="2,2,3,1",options="header"]
|===
|Handlebars |BareBars Surface |Core |Kind

|`pass:[{{helper a b}}]` |same |`pass:[{{{ esc_html (helper a' b') }}}]` |SURFACE/CORE
|positional arguments |same |evaluated left-to-right, eagerly |CORE
|string literal `"x"` / `'x'` |same |`Str "x"` |CORE
|number literal `3`, `-2.5` |same |`Num 3` |CORE
|`true` / `false` |same |`(true)` / `(false)` |ENGINE
|`null` |same |`(null)` |ENGINE
|`undefined` |`null` |`(null)` |DROPPED→`null`
|hash argument `key=value` |same |trailing `(dict "key" value')` |SURFACE
|subexpression `pass:[(helper a)]` |same |`pass:[(helper a')]` — grouping is core |CORE
|nested subexpr `pass:[(a (b c))]` |same |unchanged |CORE
|`this` as an argument |same |`this` (a nullary helper) |CORE/ENGINE
|value helper vs. block helper |arity & `pass:[#]` decide |an inline helper ignores its `Body`; a block helper uses it |CORE
|===

Worked example (from `subexpressions/`):

[source,text]
----
Handlebars:  {{upper (concat first last)}}
Core:        {{{ esc_html (upper (concat (lookup this "first")
                                         (lookup this "last"))) }}}
----

[source,text]
----
Handlebars:  {{repeat "ab" (add 1 2)}}
Core:        {{{ esc_html (repeat "ab" (add 1 2)) }}}     (literals pass straight through)
----

Hash example:

[source,text]
----
Handlebars:  {{field value required=true label="Name"}}
Core:        {{{ esc_html (field (lookup this "value")
                                 (dict "required" (true) "label" "Name")) }}}
----

[#blocks]
== A.3 Block helpers & branches

[cols="2,2,3,1",options="header"]
|===
|Handlebars |BareBars Surface |Core |Kind

|`pass:[{{#h}}…{{/h}}]` |same |`pass:[{{#h}}…{{/h}}]` |CORE
|`pass:[{{#h arg}}…{{/h}}]` |same |args desugar like any call |CORE
|`pass:[{{else}}]` separator |`pass:[{{else}}]` |a `Sep "else"` marker the block helper splits at |CORE+ENGINE
|`pass:[{{^h c}}…{{/h}}]` (HB inverted) |`pass:[{{#unless c}}…{{/unless}}]` |`pass:[{{#unless c}}…{{/unless}}]` |DROPPED→`unless`
|`else if` (chained) |same |nested `pass:[{{#if c}}…{{/if}}]` inside an `else` clause |SURFACE→ENGINE
|block params `pass:[{{#h x as \|a b\|}}]` |same |`pass:[{{#h x "a" "b"}}]` — binding-name args |SURFACE
|`options.fn(ctx)` |— |`ctx.render` over the body's non-clause nodes |ENGINE
|`options.inverse(ctx)` |— |`ctx.render` over the `else` clause found by `splitClause` |ENGINE
|`options.hash` |`k=v` on the block |trailing `dict` argument |SURFACE
|`options.data` / `createFrame` |— |the helper frame the block pushes |CORE/ENGINE
|`return new SafeString(…)` |`safe`/return `VSafe` |a `VSafe` value |ENGINE
|===

`else` has *no* meaning in the core: the parser emits a flat `Sep "else"` marker in the block's body,
and the parent helper (`if`, `each`, `with`, …) decides what a separator named `else` means by
splitting at it. The name is the engine's choice — `el`, `elif`, `case`, `default` are equally valid
(xref:concepts.adoc[] §5, xref:grammar.adoc[] §2.4).

Worked example (`block-helpers/` — `ifEquals` with an else):

[source,text]
----
Handlebars:  {{#ifEquals plan "pro"}}Pro{{else}}Upgrade{{/ifEquals}}
Core:        {{#ifEquals (lookup this "plan") "pro"}}Pro{{else}}Upgrade{{/ifEquals}}
----

Worked example (`block-helpers/` — custom `times`, exposing a scoped helper):

[source,text]
----
Handlebars:  {{#times 3}}{{@index1}}🔁{{/times}}
Surface:     {{#times 3}}{{index1}}🔁{{/times}}
Core:        {{#times 3}}{{{ esc_html (index1) }}}🔁{{/times}}
----

`times` pushes a frame per iteration and installs the scoped helper `index1`. The ENGINE writes that
helper; the core only supplies the frame plumbing.

[#builtins]
== A.4 Built-in helpers (all become ENGINE)

{hbs}' six built-ins are *not* in the BareBars core. They are reference-engine helpers
(xref:prelude.adoc[]); remove or replace any of them.

[cols="1,2,3,1",options="header"]
|===
|Handlebars built-in |Surface |Core |Kind

|`pass:[{{#if c}}…{{else}}…{{/if}}]` |same |`pass:[{{#if c'}}…{{else}}…{{/if}}]` |ENGINE
|`pass:[{{#unless c}}…{{/unless}}]` |same |`pass:[{{#unless c'}}…{{/unless}}]` |ENGINE
|`pass:[{{#each xs}}…{{else}}…{{/each}}]` |same |`pass:[{{#each xs'}}…{{else}}…{{/each}}]` |ENGINE
|`pass:[{{#with o}}…{{/with}}]` |same |`pass:[{{#with o'}}…{{/with}}]` |ENGINE
|`pass:[{{lookup o k}}]` |same |`pass:[{{{ esc_html (lookup o' k') }}}]` |ENGINE
|`pass:[{{log x}}]` |same |`pass:[{{{ log x' }}}]` (returns `VNull` ⇒ empty output) |ENGINE
|===

*Truthiness* (used by `if`/`unless`/`each`/`with`) matches {hb}: `false`, `null`, `0`, `""`, and the
empty array are falsy; `{}` and non-zero numbers are truthy. As in {hb}, `0` is falsy unless
`includeZero` is set — passed to `if`/`unless` as an options object (xref:prelude.adoc[] §6.3).

Worked example (`if-unless/` — `if` with an else and {hbs} truthiness):

[source,text]
----
Handlebars:  <p>tasks is {{#if tasks}}truthy{{else}}falsy (empty array){{/if}}.</p>
Core:        <p>tasks is {{#if (lookup this "tasks")}}truthy{{else}}falsy (empty array){{/if}}.</p>
----

Worked example (`each/` — over an object, with `@key`):

[source,text]
----
Handlebars:  {{#each profile}}<dt>{{@key}}</dt><dd>{{this}}</dd>{{/each}}
Core:        {{#each (lookup this "profile")}}
               <dt>{{{ esc_html (key) }}}</dt><dd>{{{ esc_html this }}}</dd>
             {{/each}}
----

Worked example (`each/` — empty collection renders the `else` clause):

[source,text]
----
Handlebars:  {{#each archived}}<li>{{title}}</li>{{else}}<li>Nothing archived.</li>{{/each}}
Core:        {{#each (lookup this "archived")}}
               <li>{{{ esc_html (lookup this "title") }}}</li>
               {{else}}<li>Nothing archived.</li>
             {{/each}}
----

[#data]
== A.5 `@data` variables (become scoped ENGINE helpers)

{hbs}' `@`-namespace does not exist. Each `@x` is a *scoped nullary helper* installed by the block
that introduces it; Surface drops the `@` (xref:surface.adoc[] §5.5).

[cols="2,2,2,1",options="header"]
|===
|Handlebars |Surface |Core |Installed by

|`pass:[{{@index}}]` |`pass:[{{index}}]` |`pass:[{{{ esc_html (index) }}}]` |`each`
|`pass:[{{@key}}]` |`pass:[{{key}}]` |`pass:[{{{ esc_html (key) }}}]` |`each`
|`pass:[{{@first}}]` |`pass:[{{first}}]` |`pass:[{{{ esc_html (first) }}}]` |`each`
|`pass:[{{@last}}]` |`pass:[{{last}}]` |`pass:[{{{ esc_html (last) }}}]` |`each`
|`pass:[{{@root}}]` |`pass:[{{root}}]` |`pass:[{{{ esc_html (root) }}}]` |host (top frame)
|`pass:[{{@../index}}]` |`pass:[{{@../index}}]` |`pass:[{{{ esc_html (index (parent)) }}}]` |`each` + `parent`
|custom `pass:[{{@myVar}}]` |`pass:[{{myVar}}]` |`pass:[{{{ esc_html (myVar) }}}]` |the block that frames it
|===

Worked example (`each/` — `@index`/`@first`/`@last`):

[source,text]
----
Handlebars:  {{#each people}}
               <li>{{@index}}: {{this}}{{#if @first}} — first{{/if}}{{#if @last}} — last{{/if}}</li>
             {{/each}}
Core:        {{#each (lookup this "people")}}
               <li>{{{ esc_html (index) }}}: {{{ esc_html this }}}
                 {{#if (first)}} — first{{/if}}{{#if (last)}} — last{{/if}}</li>
             {{/each}}
----

*Parent access* (`../`, the context stack) becomes the explicit `parent` helper. From `with/` and
`lookup/`:

[source,text]
----
Handlebars:  {{#with person}}{{firstname}} works at {{../company.name}}{{/with}}
Core:        {{#with (lookup this "person")}}
               {{{ esc_html (lookup this "firstname") }}} works at
               {{{ esc_html (lookup (parent) "company" "name") }}}
             {{/with}}

Handlebars:  {{#each people}}<li>{{this}} lives in {{lookup ../cities @index}}</li>{{/each}}
Core:        {{#each (lookup this "people")}}
               <li>{{{ esc_html this }}} lives in
                   {{{ esc_html (lookup (lookup (parent) "cities") (index)) }}}</li>
             {{/each}}
----

[NOTE]
====
The *idiomatic* BareBars replacement for `../` is to *name the scope* with a block parameter rather
than walk a stack: `pass:[{{#each teams as \|team\|}}…{{#each team.members}}{{team.name}}…]`. The
`parent` helper above is the mechanical, gap-free mapping; block params are the recommended style.
====

[#partials]
== A.6 Partials

[NOTE]
====
*Status.* Partials are implemented via `renderSurfaceWith`: `pass:[{{> name}}]`,
`pass:[{{> name ctx}}]`, dynamic `pass:[{{> (expr)}}]`, hash context `pass:[{{> name k=v}}]`, block
partials `pass:[{{#partial name}}body{{/partial}}]` (body = fallback + `pass:[{{> @partial-block}}]`
yield), and inline partials `pass:[{{#inline "name"}}body{{/inline}}]` (hoisted into the registry) —
see xref:flatbars-compat.adoc[compatibility matrix] §3. The core spellings `pass:[{{#partial}}]` /
`pass:[{{#inline}}]` are used in place of the Handlebars `pass:[{{#> }}]` / `pass:[{{#*inline}}]`
sigils, which the meaning-free parser does not yet match.
====

All partial forms become the engine helpers `partial` (inline and block) and `inline`, plus the
scoped `partial-block` (xref:prelude.adoc[] §6.6; xref:surface.adoc[] §5.7). The rows below show the
mapping shape; the implemented core spellings are `pass:[{{#partial}}]` / `pass:[{{#inline}}]` (see
the status note above). Partials emit *unescaped*.

[cols="2,3,1",options="header"]
|===
|Handlebars |Core |Kind

|`pass:[{{> name}}]` |`pass:[{{{ partial "name" this }}}]` |SURFACE→ENGINE
|`pass:[{{> name ctx}}]` |`pass:[{{{ partial "name" (lookup this "ctx") }}}]` |SURFACE→ENGINE
|`pass:[{{> name key=val}}]` |`pass:[{{{ partial "name" this (dict "key" val') }}}]` |SURFACE→ENGINE
|`pass:[{{> name ctx k=v}}]` |`pass:[{{{ partial "name" ctx' (dict "k" v') }}}]` |SURFACE→ENGINE
|dynamic `pass:[{{> (lookup . "layout")}}]` |`pass:[{{{ partial (lookup this "layout") this }}}]` |SURFACE→ENGINE
|partial block `pass:[{{#> layout title="T"}}body{{/layout}}]` |`pass:[{{#partial> "layout" (dict "title" "T")}}body{{/partial>}}]` |SURFACE→ENGINE
|`pass:[{{> @partial-block}}]` |`pass:[{{{ partial-block }}}]` |SURFACE→ENGINE
|inline `pass:[{{#*inline "person"}}…{{/inline}}]` |`pass:[{{#inline "person"}}…{{/inline}}]` |SURFACE→ENGINE
|partial-block *fallback* |built into `partial>` (renders body if name unregistered) |ENGINE
|`explicitPartialContext` |always on — `partial` requires an explicit context; the implicit one is the Surface sugar `partial "name" this` |HOST/DROPPED
|`preventIndent` |a `dict` option to `partial`, or a host flag |HOST
|===

Worked example (`partials/` — dynamic partial + hash):

[source,text]
----
Handlebars:  {{> (lookup . "layout") title="Chosen dynamically"}}
Core:        {{{ partial (lookup this "layout") this (dict "title" "Chosen dynamically") }}}
----

Worked example (`inline-partials/` — inline partial + partial block + `@partial-block`):

[source,text]
----
Handlebars (main):   {{#*inline "person"}}<li>{{name}} — <em>{{role}}</em></li>{{/inline}}
                     {{#each people}}{{> person}}{{/each}}
                     {{#> layout title="Team"}}<p>block content</p>{{/layout}}

Core (main):         {{#inline "person"}}
                       <li>{{{ esc_html (lookup this "name") }}} —
                           <em>{{{ esc_html (lookup this "role") }}}</em></li>
                     {{/inline}}
                     {{#each (lookup this "people")}}{{{ partial "person" this }}}{{/each}}
                     {{#partial> "layout" (dict "title" "Team")}}
                       <p>block content</p>
                     {{/partial>}}

Handlebars (layout): <div class="body">{{> @partial-block}}</div>
Core (layout):       <div class="body">{{{ partial-block }}}</div>
----

[#comments-raw-ws]
== A.7 Comments, raw blocks & whitespace

[cols="2,2,3,1",options="header"]
|===
|Handlebars |Surface |Core |Kind

|`pass:[{{! … }}]` |same |CORE comment, discarded (no `pass:[}}]` inside) |CORE
|`pass:[{{!-- … --}}]` |same |CORE long comment; may contain `pass:[}}]`/`pass:[{{]`/`--` |CORE
|raw block `pass:[{{{{raw}}}}…{{{{/raw}}}}]` |same |CORE raw block; body verbatim |CORE
|`~` whitespace control |same |CORE; resolved in the lexer |CORE
|backslash escape `\pass:[{{x}}]` |same |CORE; emits the tag literally |CORE
|standalone-line auto-trim |— |*not provided* — use explicit `~` |DROPPED
|===

Worked example (`whitespace/` + `comments/`):

[source,text]
----
Handlebars:  {{~#each items~}}<li>{{this}}</li>{{~/each~}}
Core:        {{~#each (lookup this "items")~}}<li>{{{ esc_html this }}}</li>{{~/each~}}

Handlebars:  \{{ this stays text }}
Core:        \{{ this stays text }}          (emitted literally; identical)

Handlebars:  {{{{raw}}}}Hello {{name}}{{{{/raw}}}}
Core:        {{{{raw}}}}Hello {{name}}{{{{/raw}}}}   (verbatim; `raw` engine helper returns body)
----

[IMPORTANT]
====
*The one behavioural difference.* {hbs} silently removes whitespace and the newline around a tag that
stands alone on its line. BareBars does *not*: whitespace is removed only where `~` appears.
Templates relying on standalone trimming emit extra blank lines until `~` is added — the deliberate
cost of "no implicit sugar" (xref:lexical.adoc[] §1.4). A host MAY offer an opt-in standalone pass as
a pre-lexer transform, but it is not in the core or the reference Surface.
====

[#decorators]
== A.8 Decorators

[CAUTION]
====
*Not yet implemented.* FlatBars ships no decorator helpers (including `inline`); the mapping below is
the design (xref:flatbars-compat.adoc[compatibility matrix] §3). Because a decorator is just a block
helper here, no grammar or core change is needed to add them.
====

{hbs} decorators (`pass:[{{#*helper}}]`, `pass:[{{*helper}}]`) modify a block or its `options`. BareBars
has no separate decorator concept — *a decorator is just a block helper* that wraps the body.

[cols="2,3,1",options="header"]
|===
|Handlebars |BareBars |Kind

|`pass:[{{#*inline "n"}}…{{/inline}}]` (built-in) |`pass:[{{#inline "n"}}…{{/inline}}]` engine block helper (A.6) |ENGINE
|custom block decorator `pass:[{{#*deco}}…{{/deco}}]` |an ordinary block helper returning a transformed body |ENGINE
|inline decorator `pass:[{{*deco arg}}]` |a value helper whose effect is a frame mutation it performs in `M` |ENGINE
|`registerDecorator` |`register` (same table as helpers) |HOST
|===

Because BareBars block helpers already receive the body and the frame, the decorator mechanism is
subsumed; the `*` marker is not part of the grammar.

[#options]
== A.9 Compile & runtime options

{hbs} compile/runtime flags are not template syntax; in BareBars they are *assembly choices* — which
engine you register and how its helpers/validation behave.

[cols="2,3,1",options="header"]
|===
|Handlebars option |BareBars |Kind

|`noEscape: true` |render core directly (it never escapes), or a Surface variant whose `pass:[{{ }}]` omits `esc_html` |HOST
|`strict: true` |register a `lookup` that raises `TypeError` on a missing field instead of `VNull` |HOST/ENGINE
|`assumeObjects: true` |a `lookup` variant that skips nullish guards |HOST/ENGINE
|`preventIndent: true` |a `partial` option / host flag |HOST
|`explicitPartialContext: true` |the *default* — `partial` always takes an explicit context |HOST (default)
|`knownHelpers` / `knownHelpersOnly` |inherent: only registered helpers exist; the `validate` pass rejects unknown idents up front |HOST/ENGINE
|`data: false` |omit the `@data`-style scoped helpers from the engine |HOST
|`compat: true` (recursive parent lookup) |a `lookup`/`get` variant that walks `parent` frames on a miss |ENGINE
|custom `helpers`/`partials`/`decorators` |the `Env` you pass to `render` |HOST
|===

[#api]
== A.10 JavaScript API

See xref:host-api.adoc[] §7.4 for the full table. Summary: `compile`/`precompile`/`parse` map to the
BareBars pipeline; `registerHelper`/`registerPartial`/`registerDecorator` all map to `register`
(partials and decorators are helpers); `options.fn`/`options.inverse` map to `ctx.render` over the
body's nodes / over the `else` clause; `SafeString` maps to `VSafe`/`safe`; `escapeExpression` maps
to `esc_html`; the AST `Visitor` maps to the Phase-2 `render`/`validate` walk.

[#mustache]
== A.11 Mustache-only features

[cols="2,3,1",options="header"]
|===
|Mustache feature |BareBars |Kind

|sections `pass:[{{#section}}]` (truthy / list / lambda) |write the helper explicitly: `if`/`each` |DROPPED→`if`/`each`
|inverted sections `pass:[{{^section}}]` |write `pass:[{{#unless …}}]` |DROPPED→`unless`
|implicit iterator `pass:[{{.}}]` |`this` (A.1) |SURFACE
|lambdas (functions in the data) |values are never functions; expose behaviour as a helper, or call via `apply` |DROPPED→helper
|set delimiters `pass:[{{=<% %>=}}]` |*not supported* — delimiters are fixed; a host may pre-process the source |DROPPED
|HTML-escaping by default |Surface `pass:[{{ }}]` ⇒ `esc_html`; core never escapes |SURFACE
|===

BareBars adopts *no* Mustache section syntax in any form. `pass:[{{#x}}]` *always* means "apply the
block helper `x`" — never "this is a truthy/list section over `x`" — and the inverted opener
`pass:[{{^]` is invalid: there is no such tag. Iterate with `pass:[{{#each x}}…{{/each}}]`, branch
with `if`/`unless`. (Given `{"list":[1,2,3]}`, Mustache's `pass:[{{#list}}…{{/list}}]` is *not*
BareBars; write `pass:[{{#each list}}…{{/each}}]`.)

[#engine-api]
== A.13 Implementing the second stage: the engine API

The tables above say *what* a concrete engine must mean. This section says *how* you build one — and
the defining property is that *you never write the traversal*. BareBars owns lexing, parsing,
delimiter matching, recursion into children, argument evaluation, output assembly, and error/span
propagation. Your engine plugs in a few small functions; *BareBars calls them*. This is *inversion of
control* — the Hollywood principle: **don't call BareBars; BareBars calls you.** An engine is
therefore tiny, and two engines differ only in the functions they plug in, never in traversal code.

There are two entry points, for the two things a second stage does:

[horizontal]
*interpret* (with scope):: `runTemplate` — render directly. Helpers receive a *control handle* and
ask BareBars to evaluate arguments and render children under environments the helper builds. Top-down;
BareBars owns dispatch, arg-evaluation, and assembly.
*prepare* (analyze / lower):: `foldTemplate` — a catamorphism over the skeleton. The engine supplies
an *algebra* and BareBars owns the recursion. Use it to lower the skeleton to your own typed AST, to
collect diagnostics, or to pretty-print. Bottom-up; BareBars owns the recursion.

Both invert control. Pick `runTemplate` to *execute*, `foldTemplate` to *prepare*.

[NOTE]
====
*What v1 ships.* The polymorphic `Engine m env` / `Ctl m env` / `Helper m env` and the drivers
`runTemplate` (`Monad m`) and `runString` (`MonadThrow Error m`) are implemented as shown. The
reference engine, *FlatBars*, supplies these instantiations (`renderWith`/`compile`/`renderAff` from
`FlatBars`) at both `m = Either Error` (`renderWith`/`compile`) and
`m = ExceptT Error Aff` (`renderAff`), proving the monad is pluggable; its environment is the newtype
`RefEnv m` (a type *synonym* `Env = { … Helper … Env }` would be cyclic — use a newtype). The handle
carries a `span` (the opening tag's code-unit range; `Span.lineColumn` maps it to line/column), and
`Ctl.clause`/`splitClause` return `{ before, body }`.
====

[#engine-api-run]
=== A.13.1 Interpreting: `runTemplate`

BareBars hands every helper a *control handle* `Ctl`. Everything on it is a callback *into* BareBars:

[source,haskell]
----
type Ctl m env =
  { env      :: env                          -- the current environment (yours)
  , children :: Template                     -- this block's body ([] for inline calls)
  , render   :: env -> Template -> m String  -- BareBars renders a sub-tree for you
  , clause   :: Ident -> { before :: Template, body :: Maybe Template }   -- split at a separator
  , span     :: Span }                        -- source location, for diagnostics

type Helper m env = Ctl m env -> Array Value -> m Value
----

[NOTE]
====
An earlier `Ctl` also carried `eval :: env -> Expr -> m Value` (evaluate a synthesized expression).
No helper used it — arguments arrive already evaluated as `Array Value` — so it was removed to keep
the control handle minimal. It can return without a breaking change if a future helper needs to
evaluate an `Expr` it constructs itself (e.g. a `let`/macro-style helper).
====

(Chapter 3's `Body` — `{ children, render }` — is just the slice of `Ctl` that most helpers use.)
What *you* supply is three functions; BareBars owns everything else:

[source,haskell]
----
type Engine m env =
  { initial   :: env                                -- starting environment + root context
  , resolve   :: env -> Ident -> m (Helper m env)   -- find a helper (throw UnknownHelper if absent)
  , stringify :: Value -> m String }                -- how a Value becomes output text

-- BareBars provides:
runTemplate :: forall m env. MonadThrow Error m => Engine m env -> Template -> m String
runString   :: forall m env. MonadThrow Error m => Engine m env -> String   -> m String  -- parse + run
----

The loop, which lives *inside* BareBars (informative): for each node it dispatches on the node kind;
for `Output e` it calls `eval`; for `App n args` it calls `resolve`, evaluates each argument (which
may recurse), builds a `Ctl`, and applies the helper; for `Block n args body` it does the same but
puts `body` on the handle as `children` and closes a `render` over the walk. When a block helper
wants to emit its body it calls `ctl.render` under an environment *it* constructs — and that call
re-enters BareBars, which recurses. *That re-entry is the inversion.*

A complete engine for `this`, `lookup`, `esc_html`, `if` (with an `else` clause) and `each` — note
there is no traversal anywhere in it:

[source,haskell]
----
newtype Env = Env { ctx :: Value, helpers :: Map Ident (Helper (Either Error) Env) }  -- newtype: a synonym here would be cyclic

engine :: Value -> Engine (Either Error) Env
engine root =
  { initial:   { ctx: root, helpers: base }
  , resolve:   \env n -> note (UnknownHelper n) (Map.lookup n env.helpers)
  , stringify: pure <<< stringifyValue }
  where
  base = Map.fromFoldable
    [ "this"     /\ \c _        -> pure c.env.ctx
    , "lookup"   /\ \_ (o : ks) -> pure (foldl index o ks)               -- index by each segment
    , "esc_html" /\ \_ [v]      -> pure (VSafe (escape (stringifyValue v)))
    , "if"       /\ ifH
    , "each"     /\ eachH ]

  ifH c [cond] =                                                          -- reads a nested else
    let cl = c.clause "else"
    in VSafe <$> c.render c.env (if truthy cond then cl.before else fromMaybe [] cl.body)

  eachH c [VArray xs] =                                                   -- empty -> else clause
    let cl = c.clause "else"
    in if null xs
         then VSafe <$> c.render c.env (fromMaybe [] cl.body)
         else VSafe <<< fold <$>
                traverse (\(i /\ x) -> c.render (frame c.env x i) cl.before) (zip (0 .. length xs) xs)

  frame env x i = env { ctx = x                                          -- push a per-element frame
                      , helpers = env.helpers
                          # Map.insert "index" (\_ _ -> pure (VNumber (toNumber i)))
                          # Map.insert "first" (\_ _ -> pure (VBool (i == 0))) }

run :: String -> Value -> Either Error String
run src data_ = runString (engine data_) src        -- parse Surface upstream if desired
----

BareBars matched every `pass:[{{/each}}]`, evaluated `(lookup this "x")` left-to-right, split the
`else` clause, recursed per element, and concatenated the output. The engine only stated *what each
name means* and *when to render its children*.

[#engine-api-fold]
=== A.13.2 Preparing the AST: `foldTemplate`

To *prepare* rather than execute — lower the skeleton into your own typed AST, validate it, or
print it — supply an *algebra*. BareBars drives the recursion; the block case is handed the raw
`children` (so it can resolve clauses) *and* a BareBars-provided `recurse` to fold any sub-range:

[source,haskell]
----
type Algebra a =
  { content :: String -> a
  , output  :: Expr   -> a
  , raw     :: Ident -> Array Expr -> String -> a
  , block   :: { name :: Ident, args :: Array Expr
               , children :: Template, recurse :: Template -> a } -> a   -- recurse is BareBars'
  , concat  :: Array a -> a }                                            -- combine siblings

foldTemplate :: forall a. Algebra a -> Template -> a       -- BareBars owns the traversal
----

*Lowering* a skeleton into a typed engine AST that resolves `if`/`else` into one node — the
"prepare the AST" the title asks for:

[source,haskell]
----
data Stmt = Text String | Emit Expr
          | If Expr (Array Stmt) (Array Stmt) | Loop Expr (Array Stmt) | Call Ident (Array Expr) (Array Stmt)

lower :: Algebra (Array Stmt)
lower =
  { content: \s -> [Text s]
  , output:  \e -> [Emit e]
  , raw:     \_ _ s -> [Text s]
  , concat:  join
  , block: \{ name, args, children, recurse } -> case name of
      "if"   -> let cl = splitClause "else" children
                in [ If (head args) (recurse cl.before) (recurse (fromMaybe [] cl.body)) ]
      "each" -> [ Loop (head args) (recurse children) ]
      _      -> [ Call name args (recurse children) ] }

prepared :: Template -> Array Stmt
prepared = foldTemplate lower            -- a validated, clause-resolved AST, in one call
----

The *same* `foldTemplate` is a validator when `a = Array Issue` — walk once, accumulate the
engine's schema violations with spans, no traversal written:

[source,haskell]
----
checker :: Set Ident -> Algebra (Array Issue)
checker known =
  { content: const [], raw: \n _ _ -> nameDiag known n, concat: join
  , output:  exprDiags known
  , block: \{ name, args, children, recurse } ->
      nameDiag known name <> foldMap (exprDiags known) args <> recurse children }

validate' :: Template -> Array Issue
validate' = foldTemplate (checker preludeNames)
----

[#engine-api-summary]
=== A.13.3 What BareBars does, and what you do

[cols="1,1",options="header"]
|===
|BareBars owns (you never write it) |You supply (small, declarative)

|lex, parse, match `pass:[{{/name}}]`, drop comments, apply `~`
|`initial` env / root context

|recurse into bodies; fold siblings; thread `M`
|`resolve :: env -> Ident -> m Helper`

|evaluate `Expr` trees; eval args left-to-right
|`stringify :: Value -> m String`

|build the `Ctl` handle; provide `render`/`eval`/`recurse`
|each `Helper` (what a name *means*; when to render `children`)

|attach source spans; raise structural errors
|optionally, an `Algebra` for a prepare/validate pass
|===

The xref:prelude.adoc[reference engine] (Chapter 6) is *exactly one* `Engine`: the `base` map above
grown to the full helper set, with `else`/clauses read the same way. Swap the map and you have a
different engine; the traversal — BareBars — is unchanged. That is the whole point of a construction
kit.

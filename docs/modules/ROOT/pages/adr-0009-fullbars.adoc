= ADR-009: FullBars — the reference engine and surface dialect
:navtitle: ADR-009 FullBars

*Status:* Accepted. *Date:* 2026-06-01. The middle rung of the ladder
(xref:adr-0005-dialect-ladder.adoc[]); "flat bars" to FlatBars' "bare rods."

== Context

The substrate needs *one* worked, Handlebars-faithful engine — to validate the host API (ADR-001
§A.13), to be the family's reference and Handlebars migration target, and to be the surface the other
dialects are defined against. FullBars is "one *possible* engine over the substrate" (ADR-001), not a
privileged one; the architecture must keep it swappable even as it serves as the default.

== Decision

. *FullBars = value policy + environment + prelude + lowering + surface desugar*, wired into
  convenience renderers. After the kernel extraction (ADR-003) the value policy
  (`truthy`/`escapeHtml`/`stringify`), `RefEnv`, prelude, and `lower` live in `kernel`; the `fullbars`
  package owns the *surface desugar* (`FullBars.Surface`), the convenience renderers, and the helper
  *catalog* (the single source of truth for `gen:catalog`).

. *`extras = true`.* FullBars admits the Handlebars-only shapes (raw blocks, inverse, unescaped) that
  RawBars (xref:adr-0008-rawbars.adoc[]) and MaxBars reject.

. *The surface is a desugar, not a parser* (ADR-001). `FullBars.Surface.desugar` is a pure
  `Template → Template` rewrite into core forms, then the reference renderer (or `lower`) runs the
  result unchanged. It rewrites: `pass:[{{ E }}]` ⇒ escaped `pass:[{{{ escapeHtml E }}}]`; bare/dotted
  *paths* ⇒ `lookup` chains (`name` ⇒ `lookup this "name"`, `a.b`, `a.[1]`, `../a` ⇒
  `lookup (parent) …`); `@data` ⇒ scoped calls (`@index` ⇒ `(index)`, `@root.x`); `else if` chains ⇒
  flat `pass:[{{elif}}]`; hash args `k=v` ⇒ a trailing `dict`; block params `as |item i|` ⇒ string
  args (and a bare in-scope reference ⇒ a call `(item)`); partials `pass:[{{> name ctx k=v}}]`;
  `pass:[{{#partial}}]`/`pass:[{{#inline}}]`.

. *`noLoopVars` — every bare name is a data path* (the Handlebars rule); scoped loop state is reached
  only through `@`. This is the deliberate contrast with MaxBars
  (xref:adr-0006-maxbars-loop-variables.adoc[]), which maps bare names to loop variables through the
  *same* `LoopVars` hook.

. *Safe-by-default* (xref:adr-0002-escaping-and-value-policy.adoc[]): `pass:[{{ }}]` escapes,
  `pass:[{{{ }}}]` is raw, and `escapingWarnings` flags raw output of untrusted accessors.

== Consequences

* *Pro:* one engine doubles as the Handlebars migration target *and* the catalog's source of truth;
  the surface-as-rewrite is the concrete proof of ADR-001's "no surface parser, no surface AST."
* *Note:* the Handlebars block sigils `pass:[{{#> name}}]` and `pass:[{{#*inline}}]` are now accepted
  (the core lexes them as the distinct `PartialBlock` / `Decorator` sigils — each with a clean head
  and a `pass:[{{/…}}]` close that repeats it — gated by `ParseOptions.partialBlocks` / `decorators`,
  and they desugar to the `pass:[{{#partial}}]`/`pass:[{{#inline}}]` core spellings).
* *Con:* because every other dialect is defined *relative to* FullBars, it carries gravitational
  weight despite being "just one engine" — the same tension ADR-001 logged as the
  shared-reference-lowering point.

== Amendment (2026-06-03): inline partials require the `pass:[{{#*inline}}]` decorator

FullBars now *requires* the Handlebars decorator form `pass:[{{#*inline "name"}}…{{/inline}}]`
for inline partials and *rejects* the bare `pass:[{{#inline "name"}}…{{/inline}}]` spelling with a
located `DisallowedShape` parse error. This matches Handlebars, where `inline` is a *decorator*, not
a block helper. The original "Note" above — that `pass:[{{#*inline}}]` is merely accepted and
desugars to a `pass:[{{#inline}}]` core spelling — is superseded *for the FullBars surface*: the
decorator is now the author form, and it still desugars internally to the core `inline` helper
(hoisted by `hoistInline`).

This is a *FullBars-surface-only* gate (`FullBars.checkBareInline`, which also governs the CLI
`--surface` path). The shared kernel `inline` helper is *retained* (a no-op block), so *RawBars and
MaxBars are unchanged*: they still accept bare `pass:[{{#inline}}]` (MaxBars's grammar bans the `*`
head, so bare is its only inline form). The generated helper catalog is unaffected — the helper still
exists.

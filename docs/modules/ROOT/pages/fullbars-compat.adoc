= The FullBars dialect — differences from Handlebars
:navtitle: FullBars vs Handlebars
:toc: macro
:toclevels: 2

*FullBars* is the reference engine + xref:surface.adoc[surface dialect] shipped with FlatBars
(xref:prelude.adoc[]). It is a member of the Handlebars/Mustache family: an author who knows {hbs} is
immediately at home. It is also its own *dialect* — the interesting parts are exactly where it chooses
differently, on purpose — yet it is a near-complete clone in practice.

[NOTE]
====
*FullBars matches Handlebars on 98% (49/50) of a differential conformance corpus* — every case rendered
through the real `handlebars` npm package *and* FullBars and asserted byte-identical (`conformance/handlebars/`,
gated by `npm run check:hbs-conformance`). The one corpus miss is a raw-block corner. (User-defined block
helpers, formerly a miss, are now implemented — xref:adr-0020-user-block-helpers.adoc[ADR-020], §3.) In-data
*functions/lambdas* are not a corpus target — a `Value` is pure data; a value-producing lambda is
precalculated before rendering and a section lambda is a helper (§2). This figure is *measured, not
asserted* — it cannot
over-claim what upstream Handlebars does not produce.
====

This page is written the other way round from a compatibility matrix. The *dialect* is the subject;
{hbs} is the familiar reference we contrast against. So it leads with the **divergences by design** —
the choices that give FullBars its identity, each with the reasoning — then states what it
**deliberately drops** (and the replacement), what is genuinely **not built yet**, and finally the
large surface that is simply **familiar**. For the gap-free *language* mapping (every {hbs} concept
expressed over the FlatBars core), see xref:appendix-handlebars.adoc[Appendix A].

[horizontal]
✓ Familiar:: works as a {hbs} author expects — quiet background.
◆ By design:: the same job done a considered different way — the dialect's identity.
⊘ Dropped:: deliberately not provided — a refusal, with the replacement stated.
☐ Roadmap:: genuinely not built yet — the only honest "missing".

The distinction between *⊘ Dropped* and *☐ Roadmap* is load-bearing: "we chose not to" and "we
haven't yet" are never the same row.

toc::[]

== 1. Divergences by design

These are not shortfalls; they are the dialect. Each does the same job as its {hbs} counterpart, a
different way, for a stated reason.

=== 1.1 Everything is a helper application

In the *core*, a bare identifier is a *helper call*, not a path: `pass:[{{{city}}}]` invokes the
helper `city`. To read a data field you call one — `pass:[{{{ lookup this "city" }}}]`. There are no
variables and no implicit context walk; values are pure data, helpers live in a separate scoped
environment. This is the single defining choice (xref:concepts.adoc[]), and it is what lets the core
have *no built-in names* at all.

The xref:surface.adoc[surface dialect] then restores the familiar author experience: in surface,
`pass:[{{ city }}]` *is* a data read (it desugars to `pass:[{{{ escapeHtml (lookup this "city") }}}]`),
dotted/`../`/`[bracket]` paths work, and a bare name is never a helper. So a {hbs} author writes what
they expect; the helper-first model is the *engine's* substrate beneath the sugar. Knowing which
layer you are in is the one mental adjustment porting from {hbs}.

=== 1.2 Escaping is explicit

There is no implicit HTML escaping. In core, output (`pass:[{{{ … }}}]`) is raw; escaping is the
ordinary `escapeHtml` helper, and the `escapingWarnings` lint flags *unescaped data* so "you forgot to
escape" is caught at validation, not in production. `escapeHtml` returns a `VSafe`, so re-escaping is a
no-op; `safe` is the explicit "trust this markup" (the `SafeString` analogue).

The surface dialect restores Handlebars' ergonomics on top — `pass:[{{ x }}]` ⇒ escaped,
`pass:[{{{ x }}}]` ⇒ raw — so authors get auto-escaping while the *engine* keeps escaping a visible,
auditable helper rather than a hidden rule. Same safety, explicit mechanism.

=== 1.3 `else` is a separator; `elif` is a real clause

`pass:[{{else}}]` is not a keyword — it is a *name-agnostic separator* the parser emits as a flat
marker, and the enclosing block helper (`if`/`each`/`with`/…) decides what it means by splitting on
it. A different engine could read `otherwise` or `case` instead; the core reserves nothing
(xref:grammar.adoc[] §2.4).

Building on that, `pass:[{{elif cond}}]` is a *native* clause: `if` reads a flat
`pass:[{{#if a}}…{{elif b}}…{{else}}…{{/if}}]` chain and evaluates each condition **lazily**
(short-circuit) through `Ctl.eval` — so a later branch that would error never runs once an earlier
one matches. {hbs} expresses the same shape by *nesting* `else`+`if`; FullBars makes it a first-class,
flat, short-circuiting clause rather than a desugaring trick. Surface `pass:[{{else if c}}]` lowers to
it (xref:surface.adoc[] §5.6).

=== 1.4 Safe-string truthiness is content-based

FullBars holds one invariant {hbs} does not: marking a string safe never changes its truthiness — a
safe string tests as its *content* (`truthy (VSafe s) == truthy (VString s)`), so `pass:[safe ""]` is
falsy. {hbs} instead wraps safe output in a `SafeString` *object*, which is always truthy, empty or
not. FullBars' content-based rule is the more useful one — an empty escaped section reads as empty —
so it is kept on purpose. The sharp edge to know: `safe`/`escapeHtml` *stringify* their argument, so
`pass:[(safe 0)]` is truthy (the non-empty string `"0"`) while `0` is falsy. Testing the truthiness of
an escaped/safe value is a category error — they are *output*, not data — and `escapingWarnings`
flags exactly that on `if`/`unless` conditions.

The *default* mode is familiar (Handlebars): `false`, `null`, `0`, `""`, and the empty array are
falsy; `pass:[{}]` and non-zero numbers are truthy; `0` is falsy unless `includeZero` is set, written
as the surface hash `pass:[{{#if n includeZero=true}}]`. The falsy set is **per-file configurable** via
the `pass:[{{! @truthiness: … }}]` directive (`minimal`/`presence`/`always`/an explicit shape-list) —
see xref:directives.adoc[]. With no directive, the behaviour above is exactly today's.

=== 1.5 Standalone whitespace is trimmed (on by default, configurable)

Like {hbs}/Mustache, FullBars strips a line that contains only a standalone block open/close or a
comment, so a control tag leaves no blank line. This is **on by default** (Handlebars parity).

[cols="1,3a",options="header"]
|===
|Template |Output

|`pass:[{{#each xs}}\n  <li>{{ this }}</li>\n{{/each}}]`
|*Default* — the standalone `pass:[{{#each}}]`/`pass:[{{/each}}]` lines are removed:
`pass:[  <li>a</li>\n  <li>b</li>\n]` (matching Handlebars).

|same template, with `pass:[{{! @trim: none }}]` in the header
|Trimming off — every newline is kept verbatim:
`pass:[\n  <li>a</li>\n\n  <li>b</li>\n]`.
|===

Only block opens/closes and comments are standalone-eligible. Output tags (`pass:[{{ }}]` /
`pass:[{{{ }}}]`) and bare separators like `pass:[{{else}}]` are **never** standalone-trimmed — at the
structural level a `pass:[{{ x }}]` separator is indistinguishable from surface output, so trimming it
could eat real content. Explicit `~` still works and composes on top.

Control (highest precedence first): a `pass:[{{! @trim: standalone | none }}]` header directive (the
one *syntactic* directive the core itself acts on), then the CLI `--trim`, then a `flatbars.json`
`pass:[{ "trim": … }]`, then the built-in default (on). See xref:directives.adoc[].

=== 1.6 The literals `true` / `false` / `null` are helpers

They are nullary helper calls returning `VBool`/`VNull`, not reserved words — consistent with
"everything is a helper application," and replaceable like any other prelude entry.

== 2. Deliberately dropped

A refusal, not a TODO — each with its replacement. These will not return.

NOTE: Two former entries have *moved to xref:_4_familiar_works_as_a_handlebars_author_expects[§4]*: Mustache-style implicit
sections (`pass:[{{#x}}]` over data) and `blockHelperMissing` are now implemented (see §4 and the
differential conformance harness, `conformance/handlebars/`). What remains below are the two genuine
non-clonable items — one a Mustache (not {hbs}) feature, one a consequence of the pure-data core.

[cols="2,2,3",options="header"]
|===
|Handlebars |Replacement |Why

|Mustache set-delimiters `pass:[{{=<% %>=}}]`
|fixed `pass:[{{ }}]` / `pass:[{{{ }}}]`
|A fixed grammar keeps the parser meaning-free and tooling simple. (A Mustache feature; {hbs} fixes the
delimiters too — so this is a divergence from Mustache, not {hbs}.)

|Data as functions / lambdas in the context
|precalculate the value (preprocess), or a helper for body-aware sections
|`Value` is *pure data, never a function* — the deepest core choice (xref:concepts.adoc[]). The two jobs
a {hbs}.js/Mustache lambda does live outside the value: a *value-producing* lambda is *precalculated before
rendering* (any host-side computation; the Lab uses JSONata) and passed as plain data; a *section* lambda
that rewrites its block body is a *helper* (render-time behaviour — a preprocess step never sees the
unrendered body). Engine guarantee: *no arbitrary host code runs from template data, and the rendered
`Value` stays pure and JSON-serialisable*. A deliberate substitution, not a shortfall.
|===

== 3. Roadmap

Genuinely not built yet — the only honest "missing". These would *narrow* the gap; none is a
semantic objection.

[cols="2,3",options="header"]
|===
|Handlebars |Status

|Decorators `pass:[{{*d}}]` / `pass:[{{#*d}}]`
|☐ No decorator concept shipped. A block helper already receives its body, so a decorator is just a
helper (xref:appendix-handlebars.adoc#decorators[A.8]) — none is in the prelude yet.

|User-defined *block* helpers (`registerHelper` + `options.fn`/`options.inverse`)
|☑ Implemented (xref:adr-0020-user-block-helpers.adoc[ADR-020]), FullBars. One `registerHelper`; *usage
decides* block vs inline — a block call passes a Handlebars-style `options` whose `fn(ctx)` renders the
body and `inverse(ctx)` the `pass:[{{else}}]`. The full `options` surface is `fn`/`inverse`/`hash` plus
`options.fn(ctx, { data, blockParams })` — so hash (`k=v`), scoped `@vars`, and `as |…|` block params all
work (Phase 3, via the `@hash`/`@param` channel); only `ids`/`loc`/`lookupProperty` throw.
`registerHelper` is FullBars-only — RawBars/MaxBars use
the *operation*/*definition* vocabulary (xref:adr-0019-operation-vocabulary.adoc[ADR-019]), not
`registerHelper`. This flipped the one buildable
conformance miss (`pass:[{{#bold}}]`): FullBars is now 49/50 (98%) vs Handlebars.

|Block-partial sigil `pass:[{{#> name}}]` / inline-partial decorator `pass:[{{#*inline}}]`
|☑ The FullBars author forms — they parse as plain `pass:[{{#}}]`-section blocks headed by the sigil,
with the `pass:[{{/…}}]` close resolved by `Parser.blockCloseName` (the partial name / `inline`). The
block-partial sigil desugars to the `pass:[{{#partial}}]` core spelling; the `pass:[{{#*inline}}]`
decorator desugars to the core `inline` helper (xref:surface.adoc[] §5.7). The bare
`pass:[{{#inline}}]` is *rejected* in FullBars (`FullBars.checkBareInline`, `DisallowedShape`) —
`inline` is a decorator, not a block helper. RawBars/MaxBars are unaffected (they still accept bare
`pass:[{{#inline}}]`; the core parses every form and only the surface gates the bare spelling).
|===

== 4. Familiar — works as a Handlebars author expects

Quiet background: these behave as you would expect from {hbs} (some via the surface dialect, noted).
This is the actual compatibility table.

[cols="2,2,1,3",options="header"]
|===
|Handlebars |FullBars |Status |Notes

|`pass:[{{#if}}]` / `pass:[{{#unless}}]` |same |✓ |Explicit *value* condition; `else` clause; see §1.3, §1.4.
|`pass:[{{#each xs}}]` |same |✓ |Arrays *and* objects; empty ⇒ `else`; `@index`/`@key`/`@first`/`@last` scoped helpers.
|`pass:[{{#with o}}]` |same |✓ |Shifts context; falsy ⇒ `else` (matches {hbs} 4.x).
|`pass:[{{lookup o k}}]` |`pass:[{{{ lookup o k }}}]` |✓ |More general: chains and string/number indexing.
|`pass:[{{log x}}]` |`pass:[{{{ log x }}}]` |✓ |No-op in a pure host; an effectful engine logs.
|`pass:[{{@index/@key/@first/@last/@root}}]` |surface `@`-form ⇒ scoped helper |✓ |Installed by `each` / the host.
|`pass:[{{@../index}}]` |⇒ `(parent-index)` |✓ |Enclosing loop's datum (also `key`/`first`/`last`); one `../` level.
|Paths `pass:[{{a.b.c}}]`, `pass:[{{../a}}]`, `pass:[{{a.[1]}}]` |surface ⇒ `lookup` chains |✓ |Bare/dotted/numeric/slash/`../`/`this`/`[bracket]` (xref:surface.adoc[] §5.2).
|Auto-escape `pass:[{{x}}]` / raw `pass:[{{{x}}}]` |surface ⇒ `escapeHtml` / raw |✓ |See §1.2.
|Unescaped alias `pass:[{{&x}}]` |⇒ `pass:[{{{x}}}]` |✓ |{hbs}' ampersand form, accepted as an alias of the triple-stash (the canonical spelling). RawBars/MaxBars reject `pass:[{{&}}]`.
|Comments `pass:[{{! }}]`, `pass:[{{!-- --}}]` |same |✓ |Core; discarded.
|Raw block `pass:[{{{{raw}}}}…]` |same (+ `raw` helper) |✓ |Verbatim body.
|Whitespace control `pass:[{{~ ~}}]` |same |✓ |Resolved in the lexer; see §1.5.
|Backslash escape `pass:[\{{x}}]` |same |✓ |Emits the tag literally.
|Subexpressions `pass:[(helper arg)]` |same |✓ |First-class; nesting is the norm.
|Hash arguments `pass:[k=v]` |surface ⇒ trailing `dict` |✓ |`options.hash` (xref:surface.adoc[] §5.4).
|Block params `pass:[as \|a b\|]` |surface ⇒ name strings |✓ |`each`/`with` bind them (xref:surface.adoc[] §5.5).
|Partials `pass:[{{> name [ctx] [k=v]}}]`, dynamic `pass:[{{> (expr)}}]` |surface ⇒ `partial` |✓ |`renderSurfaceWith` registers them; hash merges onto context.
|Block partials `pass:[{{#partial}}]`, `pass:[{{> @partial-block}}]` |block-aware `partial` |✓ |Body is the fallback + the `@partial-block` yield (core spelling; see §3).
|Inline partials `pass:[{{#*inline "n"}}]` |hoisted into the registry |✓ |Global to the render (the `pass:[{{#*inline}}]` decorator is required; bare `pass:[{{#inline}}]` is rejected — see §3).
|`pass:[{{else if c}}]` |⇒ `pass:[{{elif c}}]` |✓ |Native short-circuit clause; see §1.3.
|Mustache-style section `pass:[{{#x}}…{{/x}}]` over data |`blockHelperMissing`: array ⇒ `each`, truthy ⇒ `with`, falsy/empty ⇒ `{{else}}` |✓ |An unregistered block head is looked up as data and dispatched exactly as {hbs} does (`Kernel.Prelude.blockHelperMissing` / `rt.block`). The inverted form `pass:[{{^x}}]` desugars to `pass:[{{#unless x}}]`.
|`helperMissing` (inline `pass:[{{foo bar}}]`, unknown `foo`) |hard `UnknownHelper` |✓ |Matches {hbs}, which throws "Missing helper" for an unknown helper *called with arguments*; a bare `pass:[{{foo}}]` is a data read either way.
|`registerHelper` *inline* helper |same | ✓ |Escaped in `pass:[{{ }}]`, raw via `safe(…)` (xref:adr-0018-user-defined-helpers.adoc[ADR-018]).
|`registerHelper` *block* helper (`fn`/`inverse`/`hash` + `options.fn(ctx, {data, blockParams})`) |same |✓ |One registration, usage decides; hash, scoped `@vars`, and `as \|…\|` block params all work (xref:adr-0020-user-block-helpers.adoc[ADR-020]); only `ids`/`loc`/`lookupProperty` throw.
|===

== 5. FullBars extensions (no Handlebars built-in)

In {hbs} you would register these yourself or pull them from a helper library; they are part of the
FullBars prelude (xref:prelude.adoc[§6]).

[cols="2,4",options="header"]
|===
|FullBars |Purpose

|`this` |the current context value (`pass:[{{{this}}}]`)
|`true` / `false` / `null` |literal value helpers (§1.6)
|`escapeHtml` |HTML-escape a value to a safe string (the explicit auto-escape)
|`safe` |mark a string trusted (no escaping) — `pass:[VSafe]`
|`raw` |raw-block helper returning its captured body verbatim
|`dict` |build an object from `key value …` pairs (hash arguments)
|`apply` |call a helper by name (`pass:[apply "helper" arg…]`)
|`eq` / `ne` |value (in)equality ⇒ boolean (for `pass:[{{#if (eq a b)}}]`)
|`lt` / `gt` / `lte` / `gte` |order numbers/strings ⇒ boolean (mixed/other types incomparable ⇒ false)
|`not` |logical negation of truthiness
|`and` / `or` |variadic boolean fold over truthiness
|`json` / `escapeJson` |serialize a value as JSON text (`pretty=true` to indent); `escapeJson` also HTML-escapes
|`else` |the inert separator marker (renders to nothing on its own)
|===

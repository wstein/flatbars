= FlatBars ↔ Handlebars built-in compatibility
:navtitle: FlatBars compatibility matrix
:toc: macro
:toclevels: 2

*FlatBars* is the reference engine shipped with BareBars (xref:prelude.adoc[]). This page is the
concrete, per-feature status of what FlatBars *implements today* against {hb}' built-ins.

It is the engine-level companion to xref:appendix-handlebars.adoc[Appendix A]. The appendix is the
gap-free *language* mapping — it shows that every {hb} concept *can* be expressed over the BareBars
core, including engine features not yet built. This page is narrower and concrete: of those, *which
does the FlatBars prelude actually register*, and where its semantics differ from {hb}.

[TIP]
====
*Short answer.* FlatBars implements all *six* of {hb}' built-in **helpers** (`if`, `unless`, `each`,
`with`, `lookup`, `log`). The wider built-in **feature set** is broadly covered: comments, raw blocks,
whitespace control, subexpressions, `@data` variables, paths, hash arguments, partials (including
block, inline, and `@partial-block`), and block params (the last few via the
xref:surface.adoc[surface dialect]). Still missing: *decorators* and the Handlebars block-partial
*sigils* `pass:[{{#> }}]` / `pass:[{{#*inline}}]` (use the `pass:[{{#partial}}]` / `pass:[{{#inline}}]`
core spellings). FlatBars also adds helpers {hb} has no built-in for (`eq`/`ne`, `lt`/`gt`/`lte`/`gte`,
`and`, `or`, `not`,
`dict`, `apply`, `esc_html`, `safe`, `json`/`esc_json`, …).
====

[horizontal]
✅ Implemented:: shipped in the FlatBars prelude / BareBars core.
◑ Partial:: implemented with a documented limitation or behavioural difference.
✗ Not yet:: mapping is defined (see Appendix A) but no helper is registered.
➕ Extension:: FlatBars helper with no {hb} built-in equivalent.

toc::[]

== 1. Built-in helpers

{hb} documents exactly six built-in helpers. All six are FlatBars prelude helpers
(xref:prelude.adoc[§6]); none is in the engine-agnostic core.

[cols="2,2,1,4",options="header"]
|===
|Handlebars |FlatBars |Status |Notes / differences

|`pass:[{{#if c}}…{{else}}…{{/if}}]`
|`pass:[{{#if c}}…{{else}}…{{/if}}]`
|✅
|Takes an explicit *value*: `pass:[{{#if (lookup this "x")}}]`. `pass:[{{else}}]` is a name-agnostic
separator the helper splits on. `0` is falsy by default (§5); `includeZero` is supported — write the
surface hash `pass:[{{#if n includeZero=true}}]` (⇒ the options object `pass:[(dict "includeZero" true)]`).

|`pass:[{{#unless c}}…{{/unless}}]`
|`pass:[{{#unless c}}…{{/unless}}]`
|✅
|Inverse of `if`; supports the same `pass:[{{else}}]` clause.

|`pass:[{{#each xs}}…{{else}}…{{/each}}]`
|`pass:[{{#each xs}}…{{else}}…{{/each}}]`
|✅
|Iterates arrays *and* objects. An empty collection renders the `pass:[{{else}}]` clause.
`@index`/`@key`/`@first`/`@last` become the scoped helpers `index`/`key`/`first`/`last` (§2).

|`pass:[{{#with o}}…{{/with}}]`
|`pass:[{{#with o}}…{{/with}}]`
|✅
|Shifts context; a falsy context renders the `pass:[{{else}}]` clause (matches {hbs} 4.x).

|`pass:[{{lookup o k}}]`
|`pass:[{{{ lookup o k }}}]`
|✅
|More general than {hbs}': chains (`pass:[lookup o "a" "b"]`), and indexes objects by string and
arrays by number (or numeric string).

|`pass:[{{log x}}]`
|`pass:[{{{ log x }}}]`
|◑
|Registered, but a *no-op* in a pure host (returns `VNull` ⇒ empty output). An effectful engine
(`m = ExceptT Error Aff`, or a custom `log`) performs the actual logging.
|===

== 2. `@data` variables

{hbs}' `@`-namespace becomes *scoped nullary helpers* installed by the block that introduces them
(xref:appendix-handlebars.adoc#data[A.5]). The xref:surface.adoc[surface dialect] reads the `@`-form
directly (`renderSurface`): `pass:[{{@index}}]` ⇒ `(index)`; in core you call the helper, dropping the
`@`.

[cols="2,2,1,3",options="header"]
|===
|Handlebars |FlatBars (surface ⇒ core) |Status |Installed by

|`pass:[{{@index}}]` |`pass:[{{@index}}]` ⇒ `(index)` |✅ |`each`
|`pass:[{{@key}}]` |`pass:[{{@key}}]` ⇒ `(key)` |✅ |`each`
|`pass:[{{@first}}]` |`pass:[{{@first}}]` ⇒ `(first)` |✅ |`each`
|`pass:[{{@last}}]` |`pass:[{{@last}}]` ⇒ `(last)` |✅ |`each`
|`pass:[{{@root}}]` |`pass:[{{@root}}]` ⇒ `(root)` |✅ |the host (`preludeEnv` installs `root`)
|`pass:[{{@../index}}]` |`pass:[{{@../index}}]` ⇒ `(parent-index)` |◑ |`each`/`with` expose the enclosing loop's datum (also `@../key`/`@../first`/`@../last`); one `../` level only
|custom `pass:[{{@var}}]` |any scoped helper a block frames |◑ |only the prelude's set is built in
|`pass:[{{@level}}]` (log level) |— |✗ |no logging-level data variable
|===

== 3. Other built-in features

[cols="2,2,1,3",options="header"]
|===
|Handlebars |FlatBars |Status |Notes

|Auto-escape `pass:[{{x}}]`
|`pass:[{{ x }}]` via the surface dialect; core `pass:[{{{ esc_html x }}}]`
|✅
|In *core* syntax `pass:[{{ }}]` is a structural separator and output is raw `pass:[{{{ }}}]` (escape
explicitly with `esc_html`; the `escapingWarnings` lint flags unescaped *data*). The
xref:surface.adoc[surface dialect] (`renderSurface`) restores Handlebars' `pass:[{{ x }}]` ⇒ escaped,
`pass:[{{{ x }}}]` ⇒ raw, plus path rewriting.

|Paths `pass:[{{a.b.c}}]`, `pass:[{{../a}}]`
|surface dialect ⇒ `lookup` chains
|✅
|`renderSurface` rewrites bare/dotted/numeric/slash/`../`/`this`/`@data`/`[bracket]` paths to
`lookup` chains and scoped helpers (§5.2/§5.5), including `@../` parent-data for one `../` level.

|Unescaped `pass:[{{{x}}}]`
|`pass:[{{{ x }}}]` output node
|✅
|The core output form. (`pass:[{{&x}}]` is *not* supported — removed as redundant.)

|Comment `pass:[{{! … }}]`
|same
|✅
|Core; discarded.

|Long comment `pass:[{{!-- … --}}]`
|same
|✅
|Core; may contain `pass:[}}]` / `pass:[{{]` / `--`.

|Raw block `pass:[{{{{raw}}}}…{{{{/raw}}}}]`
|same (+ the `raw` helper)
|✅
|Core captures the verbatim body; the `raw` engine helper returns it.

|Whitespace control `pass:[{{~ ~}}]`
|same
|✅
|Core; resolved in the lexer.

|Backslash escape `\pass:[{{x}}]`
|same
|✅
|Core; emits the tag literally.

|Subexpressions `pass:[(helper arg)]`
|same
|✅
|First-class in the core grammar; nesting is the norm (`pass:[(lookup (parent) "k")]`).

|Standalone-line trim
|— (use `~`)
|✗
|Deliberately dropped — no implicit whitespace removal (xref:appendix-handlebars.adoc#comments-raw-ws[A.7]).

|Partials `pass:[{{> name [ctx] [k=v]}}]`, dynamic `pass:[{{> (expr)}}]`
|surface ⇒ `pass:[{{{ partial "name" ctx [(dict …)] }}}]`
|✅
|`renderSurfaceWith` registers named partials; the `partial` engine helper renders one (unescaped)
with the given context, hash `k=v` pairs merged onto it.

|Block partials `pass:[{{#partial name}}body{{/partial}}]`, `pass:[{{> @partial-block}}]`
|block-aware `partial` + `partial-block`
|✅
|`{{#partial}}` renders the named partial with its body as the fallback (if missing) and the
`pass:[{{> @partial-block}}]` yield. The Handlebars `pass:[{{#> name}}…{{/name}}]` *sigil* is not
parsed (use `pass:[{{#partial}}]`).

|Inline partials `pass:[{{#inline "n"}}…{{/inline}}]`
|`inline` (hoisted into the registry)
|✅
|`renderSurface`/`renderSurfaceWith` hoist `{{#inline}}` definitions before rendering, so later
`pass:[{{> n}}]` use them (definitions are global to the render). The Handlebars `pass:[{{#*inline}}]`
*sigil* is not parsed (use `pass:[{{#inline}}]`).

|Decorators `pass:[{{*d}}]`, `pass:[{{#*d}}]`
|an ordinary block helper
|✗
|No decorator concept; none shipped. Block helpers already receive the body, so a decorator is just
a helper (xref:appendix-handlebars.adoc#decorators[A.8]) — but none is in the prelude.

|Hash arguments `pass:[{{helper a k=v}}]`
|surface ⇒ trailing `dict`
|✅
|`renderSurface` collects `key=value` pairs into a trailing `pass:[(dict "k" v …)]` after the
positional arguments (§5.4) — `options.hash`. Values may be glued (`k=path`/`k=42`) or the next token
(`k="str"`, `k=(expr)`). This is how `pass:[{{#if n includeZero=true}}]` works.

|Block params `pass:[as \|a b\|]`
|surface ⇒ positional name strings
|✅
|`renderSurface` desugars `pass:[{{#each xs as \|item i\|}}]` to `pass:[{{#each xs "item" "i"}}]`;
`each` binds `item`=element, `i`=index/key, and `with` binds the context. A bare reference to an
in-scope param becomes a `pass:[(param)]` call (lexically scoped, including nested blocks).

|`helperMissing` / `blockHelperMissing`
|—
|✗
|An unknown helper is an `UnknownHelper` error. A custom engine's `resolve` can add a fallback, but
the reference engine has no missing-helper hook.

|Mustache sections `pass:[{{#x}}…{{/x}}]` (truthy/list/lambda)
|—
|✗
|Not supported — BareBars is not Mustache-compatible. Write the control flow explicitly with
`if`/`each` (xref:appendix-handlebars.adoc#mustache[A.11]).

|`{{else if c}}` chaining
|`elif` separator (core); surface `pass:[{{else if c}}]` ⇒ `pass:[{{elif c}}]`
|✅
|The engine's `if` reads a flat `pass:[{{elif cond}}]` clause chain, evaluating each condition lazily
(short-circuit) via `Ctl.eval` — so `else` re-testing is a real, native clause, not a desugaring
trick. The xref:surface.adoc[surface dialect] (`renderSurface`) lowers `pass:[{{else if c}}]` to it
(§5.6); parenthesize a helper condition: `pass:[{{else if (eq a b)}}]`.
|===

== 4. FlatBars extensions (no Handlebars built-in)

These have no {hb} built-in counterpart; in {hbs} you would register them yourself or pull them from
a helper library. They are part of the FlatBars prelude (xref:prelude.adoc[§6]).

[cols="2,4",options="header"]
|===
|FlatBars |Purpose

|`this` |the current context value (`pass:[{{{this}}}]`)
|`true` / `false` / `null` |literal value helpers
|`esc_html` |HTML-escape a value to a safe string (the explicit auto-escape)
|`safe` |mark a string trusted (no escaping) — `pass:[VSafe]`
|`raw` |raw-block helper returning its captured body verbatim
|`dict` |build an object from `key value …` pairs (hash arguments)
|`apply` |call a helper by name (`pass:[apply "helper" arg…]`)
|`eq` / `ne` |value (in)equality ⇒ boolean (for `pass:[{{#if (eq a b)}}]`)
|`lt` / `gt` / `lte` / `gte` |order numbers/strings ⇒ boolean (mixed/other types are incomparable ⇒ false)
|`not` |logical negation of truthiness
|`and` / `or` |variadic boolean fold over truthiness
|`else` |the inert separator marker (renders to nothing on its own)
|===

== 5. Semantic differences to watch

. *A bare identifier calls a helper.* `pass:[{{{city}}}]` invokes the helper `city`; it is *not* a
path read. To read a field, use `pass:[{{{ lookup this "city" }}}]` (xref:index.adoc[]). This is the
single biggest porting adjustment from {hbs}.
. *Truthiness matches {hbs}.* Falsy: `false`, `null`, `0`, `""`, the empty array, and a trusted empty
string (`safe ""` ⇒ `VSafe ""`). Truthy: everything else — including the empty object `pass:[{}]` and
non-zero numbers. As in {hbs}, `0` is falsy unless `includeZero` is set — the surface hash
`pass:[{{#if n includeZero=true}}]` (core: the options object `pass:[(dict "includeZero" true)]`).
+
*Safe strings (a deliberate divergence).* FlatBars holds one invariant {hbs} does not: marking a
string safe never changes its truthiness — a safe string tests as its *content* (`truthy (VSafe s) ==
truthy (VString s)`), so `safe ""` is falsy. {hbs} instead wraps safe output in a `SafeString`
*object*, which is always truthy — empty or not. FlatBars' content-based rule is the more useful one
(an empty escaped section reads as empty), so it is kept on purpose. The sharp edge to know: `safe`
and `esc_html` *stringify* their argument, so `pass:[(safe 0)]` is truthy (it is the non-empty string
`"0"`) while `0` is falsy. Testing the truthiness of an escaped/safe value is therefore a category
error — they are *output*, not data — and `escapingWarnings` flags it on `if`/`unless` conditions.
. *No implicit HTML escaping.* Output is raw by default; escape with `esc_html` and rely on the
`escapingWarnings` lint to catch unescaped data. The surface dialect (xref:surface.adoc[§5]) is where
a `pass:[{{ }}]`-auto-escapes-to-`esc_html` rewrite would live.
. *Config flags are assembly choices, not template syntax* — `noEscape`, `strict`, `assumeObjects`,
etc. map to which `lookup`/render variant the host registers (xref:appendix-handlebars.adoc#options[A.9]).

[NOTE]
====
The remaining ✗ rows (decorators, and the Handlebars block-partial sigils `pass:[{{#> }}]` /
`pass:[{{#*inline}}]`) are *roadmap items*, not core limitations. The sigil forms specifically need
the parser to reconcile the opener sigil with the close name — a deliberate concession the
meaning-free core has not made; the `pass:[{{#partial}}]` / `pass:[{{#inline}}]` core spellings cover
the same capability today.
====

= 3. Values & evaluation
:navtitle: 3. Values & evaluation

== 3.1 The abstract syntax

[source,haskell]
----
-- The parsed core. (PureScript-flavoured.)
type Template = Array Node

data Node
  = Content  String
  | Output   Expr
  | Block    Ident (Array Expr) Template (Array Branch)     -- head, args, primary body, branches
  | RawBlock Ident (Array Expr) String                      -- head, args, verbatim body

type Branch = { sep :: Ident, args :: Array Expr, body :: Template }   -- a {{sep …}} alternative

data Expr
  = Lit Value          -- only Str / Num arrive from the parser
  | App Ident (Array Expr)
----

Note there is no node for comments (the lexer drops them) and no `Group` constructor —
parentheses only affect *parsing*; `(e)` and `e` produce the same `Expr`.

A `Block` carries a *primary body* and a list of *branches*. A branch is introduced by an inline
separator `pass:[{{sep …}}]` (xref:grammar.adoc[]). *The core attaches no meaning to a separator's
name.* `else`, `elif`, `case`, `otherwise` are all just identifiers; which one (if any) a block
helper acts on is entirely the helper's business. The lexer and parser never single out a name —
this is "everything is userland" applied to control flow. The skeleton tree produced here is
validated by a separate, engine-supplied pass (the `BareBars.Walk` host module).

== 3.2 The value type (normative)

[source,haskell]
----
data Value
  = VString  String
  | VNumber  Number
  | VBool    Boolean
  | VNull
  | VArray   (Array Value)
  | VObject  (Map String Value)
  | VSafe    String          -- a string already safe to emit unescaped (see 3.6)
----

[IMPORTANT]
====
`Value` has *no function case*. Helpers are not values; they live in the environment under names
and can never be produced, stored, or passed by the language. This is the direct consequence of
"the head of an application is always a name" (xref:concepts.adoc[]). It keeps values
serializable and comparable, and it is why higher-order behaviour must go through a helper such as
`apply` rather than through the syntax.
====

`VSafe` is the only non-data case and exists solely at the output boundary; see 3.6.

== 3.3 The environment

[source,haskell]
----
type Helper = Eval -> Array Value -> Blocks -> M Value

type Env =
  { helpers :: List (Map Ident Helper)   -- a stack of frames; head is innermost
  , context :: Value                     -- what `this` returns
  }
----

* `helpers` is a *stack of frames*. Name resolution searches from the innermost frame outward; the
  first match wins. A block helper pushes a frame for its body and pops it afterward — this is the
  whole of "scope" (xref:concepts.adoc[]).
* `context` is the current data, reached only via the `this` helper. Block helpers such as `with`
  and `each` push a frame *and* set a new `context` for the body.
* `Blocks` carries the captured `body` thunk and the `branches` to block helpers (3.5). For
  non-block applications it is empty.
* `M` is the result monad. v1 fixes `M = Either Error` (pure). A host that needs asynchronous
  partials or effectful helpers may instantiate `M = Aff`; the evaluator is written against a
  `MonadThrow Error m` constraint so both work.

== 3.4 Evaluating expressions

[source,text]
----
eval(Lit v)            = v
eval(App name args)    = resolve(name) applied to [ eval(a) | a in args ]
----

`resolve(name)` searches the helper frames inner-to-outer. If no frame defines `name`, evaluation
fails with `UnknownHelper name` (xref:errors.adoc[]). A nullary application `App name []` is a
normal call with an empty argument list — there is no separate "variable" path.

Arguments are evaluated *eagerly, left to right*, before the helper runs. (Block bodies are the
exception: they are passed unevaluated as thunks — 3.5.) A helper that needs laziness over an
argument must instead be written as a *block* helper.

== 3.5 Evaluating nodes

[source,text]
----
render(Content s)                       = s
render(Output e)                        = stringify(eval(e))
render(Block name args body branches)   = stringify( resolve(name)
                                                        evaluated-args
                                                        { body, branches } )
render(RawBlock name args raw)          = stringify( resolve(name)
                                                        evaluated-args
                                                        { body = const raw, branches = [] } )
----

A *block* helper receives, in addition to its evaluated arguments, a `body` thunk and the block's
`branches`:

[source,haskell]
----
type Blocks =
  { body     :: Env -> M String                       -- render the primary segment
  , branches :: Array { sep    :: Ident               -- the separator's name (verbatim)
                       , args   :: Array Value         -- its evaluated arguments
                       , render :: Env -> M String } } -- render the segment after it
----

The helper decides whether to call `body`, how many times, with what `context`, and which extra
scoped helpers to install in the pushed frame, and it interprets `branches` however it likes. The
reference `if` renders `body` when truthy and the first branch otherwise; `each` renders `body` once
per element with a per-element frame, or the first branch when the collection is empty; `with`
renders `body` with a shifted context.

When rendering a block, the evaluator additionally installs *each separator name as a scoped helper*
that renders that branch (returning `VSafe`). This is the whole of "`else` is a scoped helper": the
core hardcodes no name, it just exposes whatever separators the author wrote. Consequently
`pass:[{{else}}]` ≡ `pass:[{{{esc_html else}}}]` ≡ `pass:[{{{else}}}]` — the `else` value is already
safe, so escaping it is a no-op.

For a *raw* block the body thunk ignores its environment and returns the captured text verbatim, so
a raw block whose helper is the identity emits its contents unchanged.

== 3.6 Stringification, escaping, and safety

`stringify` converts a `Value` to output text:

[cols="1,3",options="header"]
|===
|Value |Output
|`VString s` |`s`
|`VSafe s` |`s` (already safe; emitted as-is)
|`VNumber n` |the shortest round-tripping decimal of `n`
|`VBool b` |`"true"` / `"false"`
|`VNull` |the empty string
|`VArray` / `VObject` |host-defined; the reference host joins arrays with `","` and errors on objects
|===

[IMPORTANT]
====
*The core never escapes.* `stringify` writes strings literally. HTML escaping is the prelude helper
`esc_html`, which returns a `VSafe`. The `VSafe` tag exists so that escaping is *idempotent at the
boundary*: a helper that has already escaped its output (or deliberately produced trusted markup
via `safe`) is not escaped again when it flows through another helper. This is the BareBars analogue
of {hbs}' `SafeString`, but it is carried in the value rather than implied by which braces you typed.
Outside the output boundary, `VSafe s` compares and behaves like `VString s`.
====

== 3.7 Determinism

Given the same template, the same `context`, the same starting helper frame, and pure helpers,
rendering is deterministic and side-effect-free. Side effects (e.g. a `log` helper) are confined to
the `M` monad and are the host's responsibility.

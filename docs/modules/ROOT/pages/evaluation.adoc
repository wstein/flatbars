= 3. The skeleton AST & the walk
:navtitle: 3. AST & the walk

Phase 1 (the core) produces the *skeleton AST* defined here. Phase 2 (an engine you supply) *walks*
it to validate and render. This chapter gives the AST and the value type normatively, then specifies
the *walk contract* the reference engine, *FullBars*, implements.

== 3.1 The skeleton AST (normative)

[source,haskell]
----
type Template = Array Node
type Span     = { start :: Int, end :: Int }   -- code-unit offsets of the opening tag

data Node
  = Content  String
  | Output   Span Expr                       -- span, expression
  | Block    Span Ident (Array Expr) Template -- span, head, args, body (one sub-tree)
  | RawBlock Span Ident (Array Expr) String   -- span, head, args, verbatim body
  | Sep      Span Ident (Array Expr)          -- span, head, args (a separator marker)

data Expr
  = Lit Value          -- only Str / Num arrive from the parser
  | App Ident (Array Expr)
----

Every tag-level node carries the source `Span` of its opening tag, for diagnostics; `Content` does
not (it is literal text). `Span.lineColumn` turns an offset into a 1-based line/column.

There is no comment node (the lexer drops them), no inverse field on `Block` (branching uses `Sep`
markers; xref:grammar.adoc[]), and no `Group` constructor — parentheses affect *parsing* only, so
`(e)` and `e` produce the same `Expr`. *This tree carries no meaning.* `App "if" […]` and
`Sep "else" []` are just identifiers and arguments; whether `if` exists, what it does, and whether
`else` splits it are all Phase-2 questions.

== 3.2 The value type (normative)

[source,haskell]
----
data Value
  = VString  String
  | VNumber  Number
  | VBool    Boolean
  | VNull
  | VArray   (Array Value)
  | VObject  (Map String Value)
  | VSafe    String          -- a string already safe to emit unescaped (see 3.6)
----

[IMPORTANT]
====
`Value` has *no function case*. Helpers are not values; they live in the engine's environment under
names and can never be produced, stored, or passed by the language — the direct consequence of "the
head of an application is always a name" (xref:concepts.adoc[]). Values stay serializable and
comparable; higher-order behaviour goes through a helper such as `apply`.
====

`VSafe` is the only non-data case and exists solely at the output boundary; see 3.6.

== 3.3 The walk contract

An *engine* is anything that turns a `Template` and some data into output. The contract is one
function:

[source,haskell]
----
runTemplate :: forall m env. Monad m => Engine m env -> Template -> m String
----

The driver is *polymorphic* in the result monad `m` (a pure host uses `Either Error`; an async one
`ExceptT Error Aff`, under `MonadThrow Error m`) and in the environment type `env`. `env` is the
engine's business; the reference engine uses a frame stack (as a newtype, `RefEnv m`, so the
recursive `RefEnv → Helper → Ctl → RefEnv` is well-founded):

[source,haskell]
----
newtype RefEnv m = RefEnv
  { helpers :: List (Map Ident (Helper m (RefEnv m)))   -- a stack of frames; head is innermost
  , context :: Value                                    -- what `this` returns
  }
----

* `helpers` is a *stack of frames*. Resolution searches innermost-outward; first match wins. A block
  helper pushes a frame for its body and pops it — the whole of "scope" (xref:concepts.adoc[]).
* `context` is the current data, reached only via `this`. `with`/`each` push a frame *and* set a new
  `context`.

== 3.4 Validation is part of the walk

Before (or as) it interprets a node, the walk *validates* it against the engine's rules — exactly
like checking a JSON document against a JSON Schema:

* `App name` — is `name` a registered helper? (else `UnknownHelper`)
* arity — did `name` get the argument count it requires? (`ArityError`)
* argument shape — are the values the right kind? (`TypeError`)
* block shape — are this block's separators (`else`, `case`, …) ones this helper allows, in a
  legal arrangement? (`ClauseError`)

The *core does none of this*. A conforming engine MAY validate the whole tree up front (a static
pass, like schema validation) or lazily as it renders; the reference engine validates lazily. See
xref:errors.adoc[].

== 3.5 The reference walk

[source,text]
----
render env (Content s)            = s
render env (Output e)             = stringify (eval env e)
render env (Block name args body) = stringify (apply (resolve env name)
                                                      (ctl env body)             -- Ctl handle
                                                      [ eval env a | a <- args ])
render env (RawBlock name args r) = stringify (apply (resolve env name)
                                                      (ctl env [Content r])
                                                      [ eval env a | a <- args ])
render env (Sep name args)        = render env (Output (App name args))   -- a lone separator
                                                                          -- is just an application

eval env (Lit v)         = v
eval env (App name args) = apply (resolve env name) (ctl env []) [ eval env a | a <- args ]

-- ctl env children = { env, children, render, span, clause: \n -> splitClause n children }
----

Arguments are evaluated *eagerly, left to right*, before the helper runs. Block bodies are the
exception: a helper receives its body *unevaluated* (as a `Template`) and decides what to do with it.

== 3.6 Helpers and the control handle

*FlatBars drives the whole walk — inversion of control.* It resolves and applies each helper,
handing it a `Ctl`: a *control handle* whose fields are callbacks *into* FlatBars. A helper never
traverses the tree itself; it asks FlatBars to render the sub-trees it chooses.

[source,haskell]
----
type Ctl m env =
  { env      :: env                          -- the current environment (the engine's type)
  , children :: Template                     -- this block's body ([] for inline calls)
  , span     :: Span                         -- source location of the enclosing tag
  , eval     :: env -> Expr     -> m Value   -- FlatBars evaluates an expression for you
  , render   :: env -> Template -> m String  -- FlatBars renders a sub-tree for you
  , clause   :: Ident -> { before :: Template, body :: Maybe Template } }  -- split at a separator

type Helper m env = Ctl m env -> Array Value -> m Value
----

An *inline* helper ignores the handle. A *block* helper uses it: it may `render` its `children` zero
or more times, under environments it constructs (pushing scoped helpers, shifting `context`), and it
may `clause` to split `children` at a `{{name}}` separator.

[source,haskell]
----
-- if: render the body up to the {{else}} separator; render the else clause otherwise.
ifHelper ctl [cond] =
  let { before, body } = ctl.clause "else"
  in if truthy cond
       then VSafe <$> ctl.render ctl.env before
       else VSafe <$> ctl.render ctl.env (fromMaybe [] body)

-- ctl.clause "else" finds the first  Sep "else" _  in the children, returning
-- the nodes before it and the nodes after it.
----

`each` calls `ctl.render` once per element with a per-element frame (installing `index`, `first`,
`this`, …) and uses the same `ctl.clause "else"` for an empty-collection clause. `with` shifts
`context`. None of this is in the core — it is the reference engine's reading of the `{{else}}`
separator.

== 3.7 Stringification, escaping, and safety

`stringify` converts a `Value` to output text:

[cols="1,3",options="header"]
|===
|Value |Output
|`VString s` / `VSafe s` |`s`
|`VNumber n` |the shortest round-tripping decimal of `n`
|`VBool b` |`"true"` / `"false"`
|`VNull` |the empty string
|`VArray` / `VObject` |host-defined; the reference host joins arrays with `","` and errors on objects
|===

[IMPORTANT]
====
*The core never escapes.* HTML escaping is the helper `esc_html`, which returns a `VSafe`. The
`VSafe` tag makes escaping *idempotent at the boundary*: a value already escaped (or deliberately
trusted via `safe`) is not escaped again as it flows through another helper. This is the FlatBars
analogue of {hbs}' `SafeString`, carried in the value rather than implied by which braces you typed.
====

== 3.8 Determinism

Given the same template, context, starting frame, and pure helpers, the walk is deterministic and
side-effect-free. Side effects (e.g. `log`) are confined to `M`.

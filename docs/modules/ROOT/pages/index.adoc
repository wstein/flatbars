= BareBars
:description: A template-engine construction kit with Handlebars-style surface syntax and a sugar-free core where everything is a helper.

[.lead]
*BareBars* — _bare rods_ — is not a template engine. It is the *substrate you build one on*.

It gives you the {hbs}/Mustache surface you already know — `pass:[{{{ }}}]`, blocks,
raw blocks, comments, whitespace control — sitting on top of a *deliberately tiny core*
where almost nothing is built in. There are no built-in helpers, no escaping policy, no
control flow, and no path semantics baked into the language. Every one of those is a
*helper you supply*. You assemble the engine you want by choosing a prelude.

== What makes it different

[cols="1,3"]
|===
|No built-in helpers
|`if`, `each`, `with`, `unless`, `lookup`, `log`, and even HTML escaping are *userland*. The
core ships none of them. The xref:prelude.adoc[reference prelude] reproduces {hb}, but you can
delete, replace, or rename any of it.

|No sugar in the core
|The core grammar has no dotted paths, no `pass:[{{ }}]` auto-escaping, no `@`-variables, no
`as \|x\|` block params. All of that lives in an *optional* xref:surface.adoc[surface dialect]
that compiles to core. The core is what every layer agrees on.

|Everything is a helper application
|A bare identifier `pass:[{{{city}}}]` *calls the helper* `city`. To read a data field you call a
helper: `pass:[{{{lookup this "city"}}}]`. There are no variables and no implicit context — the
context is reached only through helpers such as `this` and `lookup`.

|Application is juxtaposition; parens group
|`pass:[{{{upcase (lookup this "name")}}}]` is `upcase` applied to one argument; the parentheses
*group* the nested application. This is the {hbs} subexpression model, used uniformly — not
Lisp prefix notation.

|`Value` is pure data
|A value is a string, number, boolean, null, array, or object. *Never a function.* Helpers live
in a separate, scoped environment, so values stay serializable.
|===

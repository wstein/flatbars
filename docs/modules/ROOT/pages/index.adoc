= BareBars
:description: A template-engine construction kit: a parser that yields a skeleton AST, plus a contract for the validating, interpreting pass an engine layers on top.

[.lead]
*BareBars* — _bare rods_ — is not a template engine. It is the *substrate you build one on*.

It is two things, and only two things:

. a *parser* that turns Handlebars/Mustache-style source into a *skeleton syntax tree* — pure
  structure, no meaning; and
. a *contract* for the *second pass* — a validating, interpreting walk over that tree — that an
  engine supplies on top.

The split is the whole idea. Think *JSON and JSON Schema*: JSON fixes a uniform structural syntax
and knows nothing about what any document _means_; a schema is a separate pass that decides which
shapes are legal and what they stand for. BareBars is the JSON; the engine you build is the schema
plus the interpreter.

== What makes it different

[cols="1,3"]
|===
|The core has no semantics
|The parser does not know what `if` does, whether output should be escaped, what a path is, or even
that an identifier names a "helper." It produces `Content`, `Output`, and `Block` nodes and stops.
All meaning is added by the xref:evaluation.adoc[engine walk].

|No built-in helpers, no keywords
|`if`, `each`, `with`, `unless`, `lookup`, HTML escaping — and `else` — are *userland*. The core
ships none of them and reserves no names. The xref:prelude.adoc[reference engine], *FullBars*, reproduces
{hbs}, but you can delete, replace, or rename any of it.

|No sugar in the core
|Dotted paths, `pass:[{{ }}]` auto-escaping, `@`-variables, `as \|x\|`, partials — all of that lives
in an *optional* xref:surface.adoc[surface dialect] that compiles to the core skeleton.

|Everything is a helper application
|In the reference engine a bare identifier `pass:[{{{city}}}]` *calls the helper* `city`. To read a
data field you call a helper: `pass:[{{{lookup this "city"}}}]`. No variables, no implicit context.

|Application is juxtaposition; parens group
|`pass:[{{{upcase (lookup this "name")}}}]` is `upcase` applied to one argument; the parentheses
*group* the nested application. The {hbs} subexpression model, used uniformly — not Lisp prefix.

|`Value` is pure data
|A value is a string, number, boolean, null, array, or object. *Never a function.* Values stay
serializable; helpers live in a separate, scoped environment.
|===

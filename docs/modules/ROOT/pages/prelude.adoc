= 6. The reference engine (prelude)
:navtitle: 6. The reference engine

The *reference engine*, *FlatBars*, is a Phase-2 walk (xref:evaluation.adoc[]) plus a set of helpers that,
together with the xref:surface.adoc[surface dialect], reproduces {hb}. *None of it is in the core.*
It is a library you register into the helper environment. Delete `each` and `pass:[{{#each}}]` stops
validating; the core is unaffected. Rename `esc_html` and update your Surface. This is what "no
built-in helpers, no keywords" buys you.

Helper signatures use the shapes from xref:evaluation.adoc[]: a helper is `Ctl m env -> Array Value
-> m Value`; a block helper uses the control handle's `children`/`clause`/`render` and may split its
`children` at a `{{name}}` separator via `splitClause`.

== 6.1 Context and access

[cols="1,1,3",options="header"]
|===
|Helper |Arity |Behaviour

|`this` |0 |Returns the current `context`.
|`root` |0 |Returns the top-level context. Installed by the host at the outermost frame.
|`parent` |0 or 1 |`(parent)` returns the enclosing block's context; `(parent (parent))` walks two
levels. Installed by block helpers that shift context.
|`lookup` |≥1 |`(lookup obj k1 k2 …)` indexes `obj` by each segment (string key or numeric index),
returning `VNull` at the first miss. `(lookup obj)` is `obj`.
|`true` `false` `null` |0 |The literal values `VBool true`, `VBool false`, `VNull`.
|===

== 6.2 Output and safety

[cols="1,1,3",options="header"]
|===
|Helper |Arity |Behaviour

|`esc_html` |1 |HTML-escapes the stringified argument (`&`, `<`, `>`, `"`, `'`) and returns a
`VSafe`. Idempotent on `VSafe` input.
|`safe` |1 |Marks the stringified argument as `VSafe` *without* escaping — the explicit "trust this
markup" helper. The analogue of `new Handlebars.SafeString(…)`.
|`raw` |block |A raw-block helper returning its captured body verbatim.
|===

== 6.3 Conditionals (clause-reading block helpers)

[cols="1,1,3",options="header"]
|===
|Helper |Form |Behaviour

|`if` |block |`splitClause "else"` over its body: renders the nodes before the `else` child when the
argument is truthy, else renders the `else` child's body.
|`unless` |block |The inverse of `if`.
|===

`if` and `unless` *define* the meaning of a nested `pass:[{{else}}…]`; the core does not.
*Truthiness* matches {hbs}: `VBool false`, `VNull`, `0`, `""`, and the *empty array* are falsy; `{}`,
non-zero numbers, and other non-empty values are truthy. As in {hbs}, `0` is falsy unless the
`includeZero` option is set — `if`/`unless` accept it as an options object,
`pass:[{{#if n (dict "includeZero" true)}}]`.

== 6.4 Iteration and context shift

[cols="1,1,3",options="header"]
|===
|Helper |Form |Behaviour

|`each` |block |Iterates an array or object. Per element it pushes a frame, sets `context` to the
element, and installs scoped helpers `index` (0-based), `key`, `first`, `last`, `parent`. Optional
binding-name arguments rename the element and index. On an *empty* collection it renders the
`else` clause (via `splitClause "else"`).
|`with` |block |Pushes a frame, sets `context` to its argument, installs `parent`, renders the body.
On a falsy/absent argument it renders the `else` clause. An optional binding-name argument also
installs the shifted context under that name.
|===

Scoped helpers installed by `each`:

[cols="1,3",options="header"]
|===
|Helper |Value inside the body
|`this` |the current element
|`index` |0-based position (number)
|`key` |property name (objects) or numeric index as string (arrays)
|`first` / `last` |`VBool` — first / last element?
|`parent` |the collection's enclosing context
|===

== 6.5 Composition / data helpers

[cols="1,1,3",options="header"]
|===
|Helper |Arity |Behaviour

|`dict` |even ≥0 |`(dict "k1" v1 …)` builds a `VObject`. Target of the hash desugaring (5.4).
|`apply` |≥1 |`(apply name args…)` — the higher-order escape hatch: `name` is a `VString` naming a
helper, applied to the remaining arguments. How a "helper held in data" is called, since values are
never functions.
|`log` |≥1 |Emits its arguments to the host log (an effect in `M`) and returns `VNull`.
|===

== 6.6 Partials

[cols="1,1,3",options="header"]
|===
|Helper |Form |Behaviour

|`partial` |2–3 |`(partial name ctx hash?)` renders the registered partial `name` with `context = ctx`,
the optional `hash` object merged onto it. *As a block* (`pass:[{{#partial name}}body{{/partial}}]`)
the body is the fallback (rendered if `name` is unregistered) and is exposed inside the partial as the
scoped `partial-block` helper. Returns `VSafe`.
|`inline` |block |`pass:[{{#inline "name"}}body{{/inline}}]` defines a partial named `name`. Definitions
are *hoisted* into the registry before rendering (`FlatBars.Surface.hoistInline`) and are global to
the render; the block itself emits `""`.
|`partial-block` |0 |Scoped helper installed by a *block* `partial`; returns the enclosing block body.
Target of `pass:[{{> @partial-block}}]`.
|===

== 6.7 A minimal engine is enough

You do not need all of the above. A static-site author might register only `this`, `lookup`,
`esc_html`, `if`, and `each`; a configuration templater only `lookup`, `eq`, and `or`. The engine —
the helpers *and* the clause vocabulary they read — is the product surface you design. The core never
presumes which of these exist.

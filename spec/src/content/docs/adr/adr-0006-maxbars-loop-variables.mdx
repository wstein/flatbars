*Status:* Accepted; the *Decision §1–2 bare loop-variable vocabulary* and the *§5 v1 outer-loop limit are
superseded by* [ADR-021](/adr/adr-0021-maxbars-variable-model/) — bare `{{index0}}`/`{{first}}`
are replaced by the namespaced `loop.*` object, and `@root`/`../` by `root`/`parent`. The
normative arithmetic this ADR fixes (§3) carries over unchanged as the `loop`-object field values, and the
§4 schema-less shadow lint is retired. *Date:* 2026-06-01. Records MaxBars Phases A/B/F (commits
`26a1f65`, `5caca26`, `8cf6c15`).

## Context

Handlebars exposes loop state through the `@` namespace (`@index`, `@first`, `../`). MaxBars wants a
richer, *bare* (no-`@`) loop-variable vocabulary that reads as ordinary scoped helpers (ADR-001 §4:
scope is scoped helpers). The cost is that bare names can shadow data fields.

## Decision

. *MaxBars-only.* FullBars stays as-is (`@index`/`@../`, via `noLoopVars`); MaxBars installs bare
  scoped helpers via `maxLoopVars` (`MaxBars.purs:41`). The richer each-frame metadata the kernel now
  exposes (Phase A) backs both.

. *Canonical set + aliases.* `index0 index1 rindex0 rindex1 first last length key`; aliases
  `index → index0`, `rindex → rindex0`, `size → length`.

. *Normative arithmetic, so interpreter and compiler cannot drift.* `index1 = index0 + 1`;
  `rindex0 = length − 1 − index0`; `rindex1 = length − index0`; `first = index0 == 0`;
  `last = index0 == length − 1`. The spec fixes these so both execution paths compute identically.

. *Shadowing is contained by a schema-aware lint.* Dropping `@` lets `first`/`key`/`length` collide
  with data fields. When a schema is present, a loop variable that collides with a declared field is
  an *error*.

. *v1 outer-loop limit (documented).* Only the outer element/index/key are reachable, via block
  params `as |user uidx|`. Outer `first`/`last`/`length`/`rindex` are *not* reachable — labelled loops
  are future work. The companion spec's claim "compute from a named outer length" is wrong: block
  params bind only the item plus index/key, so the outer length cannot be named.

. *`depth` (recursion depth) is reserved/deferred* until a recursion construct (a self-including
  partial) exists.

## Consequences

* *Pro:* ergonomic, Handlebars-free loop variables; drift-proof by construction (the normative
  arithmetic).
* *Con:* shadowing is only caught *when a schema is present* — a schema-less template can silently
  shadow a data field. The final review revisits whether the lint should also warn schema-less.

*Status:* Accepted. *Date:* 2026-06-01.

## Context

The family needs several Handlebars-lineage dialects that share one engine without copy-paste, and
*without* a premature shared-abstraction package. ADR-003 fixed *where* code lives; ADR-004 fixed
*how* a dialect plugs in its grammar. This ADR fixes the *relationship* between the dialects.

## Decision

. *The ladder: RawBars ⊂ FullBars ⊂ MaxBars.*
+
| Dialect | Surface |
| --- | --- |
| *RawBars* | the core prefix grammar directly — explicit `{{{ lookup this "x" }}}`, no sugar; `extras = false`. |
| *FullBars* | adds the surface desugar — paths, `@data`, `as \|x\|`, `{{ }}` auto-escape; `extras = true`. |
| *MaxBars* | FullBars + infix operators and pipes (`MaxBars.Expr`), desugaring to the same core `Expr`; `extras = false`. |

. *Reuse by dependency, not copy.* MaxBars depends on `fullbars` and reuses its engine, prelude, value
  policy, surface desugar, and compiler — swapping *only* the interior grammar through the
  `parseExpr`/`parseHead` seams. A shared semantic kernel is extracted *lazily*, only on a proven
  second consumer (ADR-003), never speculatively.

. *Shared compile driver + per-dialect `Emit`.* `FlatBars.Compile` is the dialect-agnostic emit driver
  — the *fourth* instance of the inversion-of-control pattern (interpret / desugar / validate /
  *compile*). `type Emit = { expr, block }` (`Compile.purs:54`); FullBars' `fullbarsEmit`
  (`Emit.purs:74`) emits native control flow for `if`/`each`/…. The conformance harness asserts the
  interpreter and the compiled JS produce byte-identical output.

. *Operators and pipes lower to existing prelude helpers.* Pipe `{{ a | f }}` → `(f a)` (piped
  value first); infix `&& || ! == != < > <= >=` → `and`/`or`/`not`/`eq`/… per the surface §B.7
  table. No new engine semantics — only new *surface*.

## Consequences

* *Pro:* one engine, four IoC instances, N dialects as symmetric packages; a new tier is a grammar
  swap, not a fork.
* *Con:* `maxbars → fullbars` is a *real* cross-dialect dependency — the single sanctioned violation
  of ADR-003's "no dialect imports another." The "⊂" is a claim about *surface supersetting*, not
  about package isolation; the two must not be conflated (see the final review).

## Alternatives considered

* *Copy FullBars into MaxBars.* Rejected: guarantees drift between the dialects' shared semantics.
* *A `common` engine package up front.* Rejected for the same reason as in ADR-003 — extract on a
  proven overlap, not on speculation.

## Amendment (2026-06-04): `⊂` is surface-superset *modulo documented exceptions*

The original decision wrote the ladder as `RawBars ⊂ FullBars ⊂ MaxBars` and the final
review pinned `⊂` as a strict *surface-superset* claim — "every FullBars template is a
MaxBars template." That overclaims: MaxBars is FlatBars' **flagship** surface, but it
deliberately does *not* accept a couple of FullBars surface constructs, so the top edge
is "most of FullBars, not quite all."

Two layers, two different truths — they must not be conflated:

* *Engine reuse by dependency is total and unchanged.* MaxBars still reuses FullBars's
  engine, prelude, value policy (truthiness aside, ADR-022), surface desugar, and compiler
  *wholesale* — swapping only the interior grammar through the `parseExpr`/`parseHead`
  seams. Nothing below the surface diverges.
* *Surface supersetting is "most, not all."* The MaxBars surface borrows the bulk of
  FullBars's surface, but rejects, by design:
+
| FullBars construct | Why MaxBars rejects it |
| --- | --- |
| the `{{#*inline}}` *decorator* | MaxBars spells inline partials with bare `{{#inline}}`; the `*`-decorator form is FullBars-only. |
| `{{> @partial-block}}` | the `@` sigil is reserved in MaxBars, which renders the caller's block body via bare `{{yield}}` instead. |
+
(Separately, MaxBars *adds* surface — operators, pipes, bare loop vars — and tightens a
few spellings where its richer grammar would otherwise be ambiguous: a clause-separator
condition and a block-head pipe must be parenthesised. Those are MaxBars-only additions,
not FullBars constructs it drops; see [maxbars](/engine/maxbars/) "v1 limitations.")

So `⊂` now reads: **surface-superset modulo the documented exceptions above**, over a
fully reused engine. The thesis of the original decision is untouched — one engine, four
IoC instances, dialects as symmetric packages, a new tier as a grammar swap not a fork.
What changes is only the *honesty of the top edge*: MaxBars is the flagship that reuses
FullBars and reinterprets its surface, not a strict superset of it.

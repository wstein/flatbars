*Status:* Accepted — 2026-06-07. An additive engine capability: a *mapped* render
that returns, alongside the output, a source map tying each run of output back to
the tag that produced it. Owner: Werner. Builds on the polymorphic interpret
driver ([ADR-001](/adr/adr-0001-structural-parser-and-walker/)) and the engine
seam ([ADR-020](/adr/adr-0020-user-block-helpers/)).

*Implementation status — complete for the core, FullBars, and MaxBars dialects.*
`Kernel.Engine` carries two no-op-by-default provenance hooks (`recordText` /
`recordEmit`); `Kernel.Provenance` runs the driver in a `WriterT` and returns
`{ output, segments }`. Each dialect exposes a mapped facade —
`RawBars.renderMapped[With]`, `FullBars.renderSurfaceMapped[With]` (generalised by
`renderSurfaceMappedDiagWith`, which MaxBars reuses), `MaxBars.renderMaxMapped[With]`
— behind the FFI (`renderMapped`, `renderSurfaceMapped`, `renderMaxbarsMapped`, each
with a `…WithPartials` twin) and the Lab's `render(.., { map: true })`. The Lab's
three-way editor↔output linking runs on it, gated by the per-dialect `source-map`
capability; `check:provenance` pins that the corpus tiles. MinBars (logic-less) emits
no segments and advertises `source-map` off, so its provenance UI gates off.

The same instrumentation backs the **Context Inspector** (`context-inspect`, the
core / FullBars / MaxBars dialects): `Kernel.Inspect.inspectResolved{Lenient,Strict}`
swaps a snapshotting `recordEmit` that, at every execution of the emit whose span +
file match a clicked run, captures the render context — `this`, the scoped vars
(`parent`/`root`/`index`/`first`/…), and the block-param `locals` — one snapshot
per loop iteration. Each dialect exposes a facade (`FullBars.inspectSurfaceWith`,
generalised by `inspectSurfaceDiagWith` which MaxBars reuses; `RawBars.inspectWith`)
behind the FFI (`inspectSurface` / `inspect` / `inspectMaxbars`) and the Lab's
`inspectAt`. MinBars gates off. Verified end-to-end by `test:lab:browser`.

## Context

The playground's signature DX is *provenance*: hover a run of output to highlight
its source tag, click it to jump there, move the caret in the source to light up
the output it produced. That needs a **source map** — for each contiguous run of
output, the originating tag's span. The Stem reference engine emitted this from
its bytecode; the FlatBars interpret driver assembles output functionally and had
no such data, so the Lab's provenance was dark for the native dialects.

Two facts make a faithful map non-trivial:

1. **Helpers can transform their body's output.** The driver does
   `h (ctl …) vals >>= stringify`, so a block helper may return something other
   than the concatenation of its rendered children. Naive leaf-logging then
   desyncs from the actual output bytes.
2. **There is no file dimension on spans, and `Content` carries none at all.**
   A span indexes *some* source; a partial's spans index the partial's own source,
   not the entry template.

## Decision

Add a mapped render that is **correct-or-absent**, never wrong.

- **No-op-by-default hooks.** `Engine` gains `recordText` and `recordEmit`. The
  reference / MinBars engines supply no-ops, so an unmapped render records nothing
  and stays **byte-identical** — the compiler≡interpreter invariant
  ([ADR-011](/adr/adr-0011-compile-to-js/)) holds (`test:compile` green).
- **A writer + a tiling check.** `Kernel.Provenance` instantiates the *same*
  polymorphic driver at a `WriterT` that logs a run per leaf, then verifies the
  logged runs reconstruct the output exactly before returning them. A transforming
  block helper fails the check and the map degrades to `[]` — the capability gates
  off rather than lying.
- **`recordEmit` uses `listen` to avoid double counting.** An emit whose
  expression itself logged sub-runs (a partial expanding its body) adds no outer
  run — the sub-runs already cover it. So partials tile *fine-grained*.
- **Each run carries its source file.** The env threads a `currentFile` (and a
  per-partial `partialFiles` map the mapped facades populate); `partialH` shifts it
  when expanding a partial, so a partial-origin emit links to its *own* source — an
  external partial to its document, an inline-hoisted one to where it is defined
  (`"main"`). The entry template is `"main"`.
- **Offsets are JS string indices.** PureScript `String` is UTF-16, like a JS
  string, so `out`/`len`/`start`/`end` are code-unit offsets the browser consumes
  with no byte↔char conversion.

A `Segment` is `{ out, len, kind, file, start?, end? }`: `out`/`len` locate the run
in the output, `kind` is `"text"` | `"emit"`, `file` is its source document, and
`start`/`end` are the tag's span in `file` (present on `emit` runs). The segments
tile the output: ordered, contiguous, each `len > 0`, covering `[0, output.len)`.

## Consequences

- The FullBars-surface provenance UI lights up; the other dialects gate off
  honestly via their capability vector.
- Templates whose output is reshaped by a transforming helper get no map for that
  render (degrade to `[]`), which is correct, not broken.
- Follow-up: a defended Lab boot path (the `§9` review item) — wrap the
  engine/examples fetch in a visible fallback instead of a blank page.

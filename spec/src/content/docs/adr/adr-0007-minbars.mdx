*Status:* Accepted (implemented). *Date:* 2026-06-01.

:::note
*Conformance (full official `mustache/spec`).* MinBars passes *184/184 (100%) of every Mustache module
it implements* — all six required modules plus the optional `~dynamic-names` and `~inheritance`. Measured
against the spec's own `expected` (`conformance/mustache/`, gated by `npm run check:mustache-conformance`),
over the *whole* vendored suite, so it cannot over-claim.

*Lambdas live outside the value, by design.* The optional `~lambdas` module is not a target: a Mustache
lambda is a *function embedded in the data*, and a `Value` is *pure data, never a function*
([concepts](/concepts/)). The two jobs a lambda does map to two places, neither inside the value — a
*value-producing* lambda is *precalculated in a preprocess step* (any host-side computation; in the Lab,
the JSONata transform) and rendered as plain data; a *section* lambda that rewrites its block body is a
*helper/block helper* (render-time behaviour — preprocessing never sees the unrendered body). The
engine-level guarantee is narrow but real: *no arbitrary host code runs from template data, and the
rendered `Value` stays pure and JSON-serialisable*. JSONata is the Lab's tool for the preprocess step, not
an engine dependency — the engine, CLI and compiled output only ever receive plain data.
:::

## Context

A Mustache-compatible engine completes the family. The key decision is its *position*: MinBars is a
*peer* of ClassicBars, not a desugar over it. The lattice becomes RawBars ⊂ MinBars (Mustache) and
RawBars ⊂ ClassicBars ⊂ MaxBars, with MinBars and ClassicBars as siblings over the shared kernel.

The draft spec was reviewed against the real code; that review found several "core is reused
unchanged" claims to be false. They are recorded here because they reshape the plan.

## Decision (locked)

1. *Scope = the full Mustache spec in one pass* — interpolation, sections, inverted, comments, partials,
   dotted names, implicit iterator, standalone whitespace — *plus* inheritance
   (`{{<p}}`/`{{$b}}`/`{{<*}}`/`{{/*}}`) and dynamic-name partials
   (`{{>* }}`). Lambdas are dropped (`Value` has no function arm). Set delimiters
   (`{{=<% %>=}}`) were initially deferred but are now *implemented* MinBars-exclusively
   ([ADR-015](/adr/adr-0015-set-delimiters/) + 2026-06-04 scope narrowing; RawBars / MaxBars /
   ClassicBars reject the inline form). MinBars passes the full `delimiters` module, 14/14.

1. *Truthiness `mustache` default = a shared parameter.* Add `mustache = false null []` to the alias
   table *and* thread a per-engine default `FalsySet` through `resolveTruthiness` + `runResolved`
   (today `handlebars` is hardwired, `Value.purs:69`); update the RawBars/ClassicBars/MaxBars call sites to
   pass `handlebars` explicitly. Recursion budget default = 64.

1. *Conformance harness = a Node-side runner* (`.mjs`, mirroring `packages/compile/conformance.mjs`)
   against built `output/`, using the mustache/spec *`.json`* fixtures — built-in `JSON.parse`, *no*
   YAML dependency.

1. *Build the shared recursion guard now* — a kernel depth/budget (error past 64) that also hardens the
   reference engine's currently-unbounded `partialH` (`Prelude.purs:501`).

## Substrate corrections the review found

These were wrong in the draft spec; verified in the code:

* The IoC driver *is* env-polymorphic (`Engine m env`) — but `refEngine` is hardwired to `RefEnv`, so
  MinBars writes its *own* `Engine m MinEnv`. `MinEnv` must be a *newtype* (the `env → Helper → Ctl`
  reference is cyclic). Use a closed `resolve` mapping the desugar's fixed helper names to the MinBars
  prelude — no helper-registry frame needed.
- * `Ctl.render  — env -> Template -> m **String**` (not `m Value`) — section/inverted helpers must
  ``VSafe &lt;$> ctl.render …`` then `joinWith ""`, like `eachH`; the spec's helper snippets were
  type-wrong as written.
* The core lexer recognises a *fixed* sigil set with *no* per-engine seam. Plain-Mustache sigils
  already exist, but `{{<`/`{{$`/`{{>*`/`{{<*`/`{{/*` are *new* and
  must be added to the *shared* core lexer/parser, gated like `extras` ([adr-0004-token-lexer-and-grammar-seams](/adr/adr-0004-token-lexer-and-grammar-seams/)).
  "Core reused unchanged" is false.
* Standalone whitespace is already shared and default-on (`trimStandalone`); the genuinely new work is
  *partial/inheritance indentation re-application*, not the standalone pass.
* `escapeHtml` already escapes `& < > " '` and not backtick/`=` — already Mustache-conformant,
  reuse it ([adr-0002-escaping-and-value-policy](/adr/adr-0002-escaping-and-value-policy/)).
* MinBars supplies its *own* prelude: the reference `partialH` *throws* on a missing partial (Mustache
  wants `""`) and Mustache *inherits* the context stack.

## Consequences

* *Pro:* completes the family and forces three genuinely reusable kernel upgrades — the per-engine
  truthiness default, the recursion guard, and the gated-sigil mechanism. MinBars is the *proven
  second consumer* that justifies these extractions under ADR-003's "extract lazily" rule.
* *Con:* the "core is reused unchanged" folklore dies; every new gated sigil enlarges the shared
  lexer's fixed vocabulary — the ADR-004 *Con* realised for the first time.

## Phase plan

P0 shared prereqs (truthiness default param + `mustache` set; recursion guard; gated core-lexer
Mustache shapes) → P1 `minbars` package + own `Engine`/`MinEnv` + prelude + desugar → P2 core
semantics → P3 inheritance + dynamic-names → P4 standalone + indentation → P5 Node conformance harness.

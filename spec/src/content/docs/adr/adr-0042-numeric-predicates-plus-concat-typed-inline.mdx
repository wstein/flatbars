*Status:* **Accepted** (surface frozen here; implemented smallest-first — see §7). *Date:* 2026-06-11.
Applies to the **MaxBars** surface (the PureScript reference / oracle for the Trussbars production
engine) and its two backends — the AOT Rust emitter (`MaxBars.Rust` → `trussbars-std`) and the VM
(`trussbars-vm`). Builds on the prelude single-source rule
([catalog convention](/concepts/)) and the dialect ladder of
[ADR-005](/adr/adr-0005-dialect-ladder/); follows the discipline that *author-facing surface syntax
is frozen in an ADR before the implementation PR*.

## 1. Context

The northstar survey ([`trussbars/docs/24-northstar-migration.md`](https://codeberg.org)) put **Zola
(Tera)** as the lead migration target, which prompted a feature-by-feature comparison of Tera/Zola
against MaxBars/Trussbars. Three Tera/Jinja constructs have no MaxBars equivalent *yet* but map
cleanly onto the typed, fixed-vocabulary, injection-safe model — and each is **more** idiomatic in
Trussbars than in its source language *because* Trussbars is typed:

1. **Numeric predicates.** Tera/Jinja spell `if n is even` / `is odd` / `is divisible_by(3)`. MaxBars
   already ships the *membership* and *affix* predicates (`includes`, `startsWith`, `endsWith`) but
   has **no numeric-parity predicate** — you must write `(eq (modulo n 2) 0)` by hand.
2. **String concatenation.** Tera/Jinja/Twig spell concatenation with the `~` operator. MaxBars has
   **no concatenation operator** at all (you reach for the `append`/`prepend` helpers). Because the
   northstar is a **Zola/Tera migration**, MaxBars adopts Tera's exact `~` spelling — a ported
   template's `name ~ "!"` reads unchanged — while the typed engine removes the *reason* `~` exists in
   Jinja (disambiguating an overloaded `+`): here `~` is the *only* concat spelling and `+` stays
   strictly numeric.
3. **Macros with signatures.** Tera's `{% macro card(title, badge="") %}` are *untyped* — a wrong
   call is a runtime error. MaxBars already has parameterised partials (`{% inline "card" %}` +
   `{% include "card" title=x %}`, the hash merges onto the partial context), but **no declared
   parameter list** — so there is no arity/spelling contract and no place to hang AOT types.

This ADR freezes the surface for all three. It deliberately picks the *fixed-vocabulary* shape over
new sigils wherever the prelude can carry the meaning (predicates), and reuses existing machinery
(the include-hash for inline parameters) rather than inventing a call syntax.

## 2. Decision — numeric predicates as prelude value operations

Add three **value operations** to `Kernel.Prelude` (the single source — the catalog, the VM, and the
AOT emitter all derive from it):

| Operation | Arity | Meaning | Desugars from |
| --- | --- | --- | --- |
| `even` | unary | `True` when the number is even | call `(even n)` / pipe `n \| even` |
| `odd` | unary | `True` when the number is odd | call `(odd n)` / pipe `n \| odd` |
| `divisibleBy` | binary | `True` when the first number is divisible by the second | call `(divisibleBy n 3)` / pipe `n \| divisibleBy 3` |

They are plain operations — **no `is` infix sugar** (rejected in §5). They read naturally in both the
output and guard positions MaxBars already supports (in a block head a helper application is
parenthesised, MaxBars' existing rule — a bare pipe there collides with block-param syntax):

```truss
{{ n | even }}                                          {# output: "true" / "false" #}
{% if (n | even) %}even{% elif (divisibleBy n 3) %}fizz{% endif %}
```

- **Type:** both consume `Number`, produce `Bool`. A non-number is a `TypeError` (same rule as the
  arithmetic operations — no string coercion, deterministic across backends).
- **`even`/`odd`** are defined against the same `jsMod` used by `modulo`, so `even n ≡ eq (modulo n 2) 0`
  bit-for-bit on every backend. `odd` is `not even` (never a second parity computation, so the two
  can't drift).
- **`divisibleBy n d`** is `eq (modulo n d) 0`. `d = 0` follows `modulo`'s existing `d = 0` behaviour
  (no new edge rule).

The names are MaxBars-canonical (camelCase `divisibleBy`, matching `startsWith`/`endsWith`); the
Tera/Jinja spelling `divisible_by` is **not** an alias (MaxBars has never mirrored snake_case
spellings — see `startsWith`, not `starts_with`).

## 3. Decision — `~` is the string concatenation operator (Tera's spelling; no `+` overload)

A new infix operator `~` joins MaxBars at **additive precedence** (beside `+`/`-`), desugaring to a
new prelude operation `concat` — the same spelling and meaning as Tera/Jinja:

| Left | Right | `~` means | Result |
| --- | --- | --- | --- |
| `String` | `String` | concatenation | `String` |
| mixed (e.g. `String ~ Number`) | | **error** | — |

`+` stays **strictly numeric** — it is *not* overloaded. Concatenation lives on its own operator so
the two never have to be disambiguated by their operand types at a glance, and `+`'s byte-identical
numeric codegen is untouched. Adopting Tera's `~` (rather than an `+` overload or the
Haskell-flavoured `++`) is a deliberate **migration** choice: a Zola/Tera template's `~` ports
verbatim. Where Jinja's `~` exists to *paper over* an ambiguous overloaded `+` (so `"1" ~ 1 == "11"`
coerces silently), MaxBars keeps the `~` spelling but **not** the coercion — mixed/non-string operands
are a `TypeError`, surfacing the bug the typed engine can see.

- **Lexer:** MaxBars (which owns its front-end, [ADR-041](/adr/adr-0041-per-surface-lexer-parser/))
  lexes `~` as the operator token `TOp "~"` (a new entry in MaxBars' operator set).
- **Parser:** `MaxBars.Expr` parses `a ~ b` at the additive rung into `concat a b` (left-assoc, like
  `+`).
- **Oracle (PureScript):** `concat` is a binary operation — two `VString` → `VString`; any other
  operand pairing is a `TypeError` (no coercion, deterministic across backends, same discipline as
  the arithmetic operations).
- **VM:** the `("concat", [a,b])` dispatch mirrors the oracle — two strings concatenate, else
  `TypeError`.
- **AOT (typed):** `concat` emits `trussbars_std::concat(&a, &b) -> String`. Because the emitted
  helper takes string references, a non-string operand is a **Rust compile error** — AOT rejects at
  build time exactly what the oracle/VM reject at render time, with no type information threaded into
  the emitter.

The existing `append`/`prepend` *affix* helpers stay (fixed argument order, a different ergonomic from
the symmetric operator). Concatenation of more than two pieces chains naturally (`a ~ b ~ c`). Array
concatenation is a **natural future extension** of `~` (sequence concat) but is out of scope here —
`~` is string-only for this increment (strings are ~all template concatenation), and widening it
later is additive.

## 4. Decision — typed `{% inline %}` signatures

An `{% inline %}` definition may declare a **parameter list** after its name:

```truss
{% inline "card" (title, badge="") %}
  <article><h3>{{ title }}</h3>{% if badge %}<span>{{ badge }}</span>{% endif %}</article>
{% endinline %}

{% include "card" title=post.name badge="new" %}
{% include "card" title=post.name %}            {# badge defaults to "" #}
```

The signature is `( name ( , name ( = default )? )* )` — comma-separated parameter names, each with an
optional default that is a **literal** (string/number/bool/null) or another in-scope nullary operation
value. The body binds each parameter as a **local** sourced from the matching `{% include %}` hash
argument; a parameter with no matching hash arg falls back to its default, and a parameter with
**neither** a hash arg nor a default is a located error at the include site (the typed-macro contract
Tera lacks).

- **Surface parse:** `MaxBars.Parser`'s inline-head parser (MaxBars owns its front-end per
  [ADR-041](/adr/adr-0041-per-surface-lexer-parser/)) gains an optional `( … )` after the partial
  name. The empty signature `{% inline "x" %}` is unchanged (no list = today's "merge the whole
  include hash" behaviour, preserved for back-compat).
- **Desugar / binding:** a signed inline desugars to the body wrapped so each declared parameter
  resolves to `hash-arg ?? default`, scoping the names as locals (the existing `{% include %}` hash
  already lands on the partial context — the signature *names and bounds* what it carries, rather
  than changing how it is passed).
- **AOT typing (the differentiator):** the schema-inference pass (`inferMax`) reads the signature to
  type each parameter from its call-site argument (and checks the default's type agrees), so a
  missing required argument or a type-mismatched argument is a **compile-time** error — a typed macro,
  which Tera's untyped `{% macro %}` cannot offer.
- **Call syntax is unchanged:** `{% include "card" k=v %}` already exists (ADR-039 §5.7); the
  signature adds the *declaration* side only. No new call keyword (`{% call %}` etc.) is introduced.

Required-vs-optional is positional-free (every argument is a named hash key), so reordering and
partial application read the same as today; the signature only adds the *names + defaults + types*.

## 5. Rejected alternatives

- **`is even` / `is divisible_by(n)` infix (Tera/Jinja "tests").** Rejected: a new `is` keyword + a
  test namespace duplicates the operation vocabulary for one read-aloud nicety. MaxBars already reads
  cleanly with the pipe (`n | even`) and the call (`even n`), both of which reuse the *one* fixed
  operation vocabulary (ADR-019) the catalog, hover, and linter already know. A bespoke `is` grammar
  would need its own paint, its own diagnostics, and its own catalog projection for zero new meaning.
- **Overloading `+` for concat (type-directed `+`).** Rejected in favour of the dedicated `~`: a
  separate operator is clearer at a glance (no "is this `+` numeric or string?"), keeps `+`'s numeric
  codegen byte-identical, and avoids monomorphising a `Plus` trait.
- **`++` for concat (Haskell/Elm/Gleam spelling).** Considered, but rejected in favour of Tera's `~`:
  the northstar is a Zola/Tera migration, so matching Tera's operator verbatim lets ported templates'
  `~` carry over unchanged — the migration parity outweighs `~`'s general unfamiliarity (and `~` here
  is *less* surprising than in Jinja, since it can never silently coerce).
- **`{% macro %}` / `{% call %}` as a new construct.** Rejected: `{% inline %}` + `{% include k=v %}`
  already *is* the parameterised-partial machinery; adding a parallel macro construct would fork the
  partial registry and the include path for no capability the signature (§4) doesn't already give.
- **Positional macro arguments (`{% include "card" x y %}`).** Rejected: MaxBars partials are
  context-merge, not positional-apply; named hash args are the established, reorder-safe call shape.

## 6. Consequences

- **One new vocabulary increment.** Four operations (`even`/`odd`/`divisibleBy` + the `~`-backing
  `concat`) enter the prelude, so `gen:catalog` / `gen:operations` regenerate and the catalog, LSP
  hover, and TextMate/`operations.json` painter pick them up for free (the single-source rule pays
  off). The inline signature adds **no** new operation name. `~` is a new operator token but reuses
  the existing infix-desugar machinery.
- **Backends stay in lockstep.** Each addition lands in all three of oracle / AOT / VM and is pinned by
  the trussbars conformance harness (oracle ≡ AOT ≡ VM, byte-identical) plus a `test:compile` case —
  no backend can drift.
- **AOT gains a genuinely typed macro** (§4) — a Zola/Tera migration headline: "same templates, but a
  wrong macro call is a *compile* error."
- **No new runtime primitive.** Predicates and `concat` are prelude operations; `~` is sugar for
  `concat`; inline signatures desugar to existing local-binding + include-hash machinery. Nothing new to the engine
  core or the VM opcode set.

## 7. Implementation order (smallest-first)

1. **Numeric predicates** — `Kernel.Prelude` (`even`/`odd`/`divisibleBy`) + `MaxBars.Rust` call-table
   + `trussbars-std` (`even`/`odd`/`divisible_by`) + `trussbars-vm` dispatch + `gen:catalog`/
   `gen:operations` + conformance cases + MaxBars tests.
2. **`~` concat** — the `concat` operation in the oracle + VM; the `~` token in `MaxBars.Lexer`
   and the additive-rung parse in `MaxBars.Expr`; `trussbars_std::concat` and the `concat` emit in
   `MaxBars.Rust`; `gen:catalog`/`gen:operations`; conformance + `test:compile` cases.
3. **Typed `{% inline %}` signatures** — `MaxBars.Parser` head, the binding desugar, the `inferMax`
   typing, the include-site arity/type check; conformance + tests; `engine/maxbars.mdx` + the
   `/maxbars` tutorial.

Each is a self-contained, separately-committed, fully-green increment (the surface is frozen here, so
no spelling churn mid-implementation).

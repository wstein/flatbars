*Status:* Accepted — *implemented* 2026-06-06. Extends [ADR-022](/adr/adr-0022-analyse-mode/) (analyse
mode, the data-driven truthiness portability check): same `Decision` trace, same named-rule menu, same
`reportMarkdown`/`findings`/`jsonataScaffold` outputs. Reuses the host-pluggable-callback pattern of
[ADR-022](/adr/adr-0022-analyse-mode/) (`Truthy`) and [ADR-029](/adr/adr-0029-i18n-helper/)
(`Translator`) for the new `PathSchema` seam. Respects the meaning-free thesis of
[ADR-001](/adr/adr-0001-structural-parser-and-walker/): no schema is baked; the host plugs it in.

## Context

Analyse mode (ADR-022 Part B) renders a template against *real data* and observes every truthiness
decision the engine made, flagging the ambiguous four (`0` `""` `[]` `{}`) when a named rule would branch
the other way. It is genuinely useful — but it has one structural weakness that a team review surfaced:

* *It only sees what the sample data exercises.* The report literally says "_no portability findings — for
  that data_". A green run on `{ "count": 5 }` says nothing about `count: 0`. "No findings" reads as "safe"
  but proves only "safe for this one sample" — a footgun.
* *The fix can't be "provide better data".* Hand-crafting adversarial data for every path does not scale, and
  the engine has no schema to reason about which values a path can hold (ADR-001: types are a host concern).

The goal is to decouple *coverage* from the data sample without baking a type system into the meaning-free
core, and to make "no findings" honest about its scope.

## Decision

1. *Symbolic what-if (potential findings).* For every condition whose *observed* value is **not** one of the
   ambiguous four and not always-falsy (`false`/`null`), derive the *same-type* ambiguous value — a number ⇒
   `0`, a non-empty string ⇒ `""`, a non-empty array ⇒ `[]`, a non-empty object ⇒ `{}` — and emit a
   **potential finding** ("`count` (observed `5`) would diverge if it ever holds `0`"). This is a pure
   post-process over the recorded `Decision`s — no extra render, no new wrapper — so its output is a function
   of the *template*, not the sample, which is what CI wants to gate. A *bare-path* condition carries its
   data path and JSONata fix; a *computed* condition (`{{#if (and a b)}}`) gets the same type-based
   potential finding without a targetable path (the generation half of the review's #1/#5, unified).

1. *Coverage honesty.* Every `Finding` gains a `kind` (`"observed"` vs `"potential"`), and `reportMarkdown`
   states what it checked: _N conditions evaluated · M observed · K potential_, with potential findings in
   their own clearly-hypothetical section ("_would diverge if …_"). "No observed findings" can no longer be
   misread as "portable for all data".

1. *Optional host `PathSchema` seam.* A host may plug in `PathSchema = String -> Value -> Boolean`
   ("could this path hold this value?") — seeded exactly like `Truthy` (ADR-022) and `Translator`
   (ADR-029), **not** baked. A potential finding for path `p` and ambiguous value `av` is suppressed when
   `schema p av == false` (the host's types rule it out: "`count` is always a present positive number").
   Default is `\_ _ -> true` (no schema ⇒ every what-if stands), so it costs nothing when unused and never
   violates the meaning-free core.

1. *Data-access misses as an advisory finding.* Analyse also wraps `lookup`, recording bare paths that
   resolve to absent/`null`. These surface as `kind: "miss"` findings ("`user.naem` resolved to null for this
   data — likely a typo"), the highest-signal typo catcher we have. Like every data-observed signal they are
   *advisory* and carry the same coverage caveat ("for this data").

1. *Lint stays static; analyse owns data + symbolic.* The split from the review holds: `flatbars lint`
   remains static, value-free, and CI-gating (aliases, scoped variables, i18n usage); analyse owns everything
   data- or symbolic-driven and stays *advisory* — observed/miss findings depend on the sample, and only the
   symbolic *potential* findings (a function of the template) are stable enough to gate. They cross-link, they
   do not merge.

## Consequences

* The facade `analyze(template, data)` returns observed **and** potential **and** miss findings (each tagged
  `kind`), and the report leads with the coverage line. `analyzeWith(schema, template, data)` adds the host
  `PathSchema`. The Lab Truthiness panel groups by `kind`; `/analyse` teaches "observed vs potential".
* The named-rule machinery, the `recoverPath`/`fixFor`/`describe` helpers, and `jsonataScaffold` are reused
  unchanged — potential findings emit the same JSONata cleanup for their (hypothetical) path.
* No new render pass: symbolic findings are derived from the existing `Decision` trace, so analyse stays a
  single pure render (`WriterT (Array Decision) (Either Error)`), no `Effect`/`Aff`.
* The `PathSchema` seam is the third instance of the same pattern (truthiness, i18n, now schema) — the host
  supplies meaning, the core stays meaning-free.

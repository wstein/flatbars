engine semantics. The de-risk spike succeeded and was carried to a full build: a
Markdown twin of the helper catalog, a reproducible AsciiDoc→MDX converter, and the
*entire* 45-page spec (31 ADRs included) now build in Astro Starlight with Pagefind
search and `starlight-links-validator` reporting every internal link valid. That
green build validates the decision, so it is Accepted. Owner: Werner. Honours the
design-system single-source-of-truth contracts of
[ADR-017](/adr/adr-0017-editor-support-lsp/) (tokens, vocabulary, one wordmark) and
keeps the spec as the contract the packages target
([ADR-001](/adr/adr-0001-structural-parser-and-walker/)).

*Implementation status — complete.* The cutover is done: Antora, its playbook, and
the one-time AsciiDoc→MDX converter are removed, and the committed MDX under
`spec/src/content/docs/` is the maintained source. The content-fidelity pass ran
first (description lists became bullets; the one PlantUML diagram is a
dependency-free ASCII flow — richer Mermaid rendering is the remaining follow-up),
so no conversion artefacts were locked into the contract. The four `docs/`-reading
gates were repointed to the MDX (`check:catalog` emits only the MDX partial,
`check:adr-nav` validates `src/sidebar.ts`, `check:glossary` reads the MDX,
`gen:tokens` drops the docs copy), and the deploy workflow builds the Starlight
site at `/flatbars/spec/`. Mermaid diagram rendering (astro-mermaid) and a live
engine pane (the real engine, in `concepts`) have since shipped. *Versioning is
deliberately deferred:* while `content/docs` **is** 0.1.0, a `starlight-versions`
snapshot is a byte-identical duplicate of the whole contract (46→91 pages) with no
reader value — the bloat D3 limits. Enable it at the 0.2.0 cut (one config line;
see `spec/astro.config.mjs`).

## Context

The normative spec in `docs/` is the contract the PureScript packages target — 46
AsciiDoc pages (≈7,360 lines), of which 31 are ADRs, built today by Antora
(`npm run docs`). Antora has served well but carries friction this project keeps
hitting:

* *It builds from git HEAD, so a linked worktree cannot build it in place* — a
  recurring footgun for a repo that uses worktrees.
* *AsciiDoc cannot import the live engine.* The learner site (`tutorials/`, Astro 6 +
  Preact) renders *real* engine output inline by importing `lab/vendor/flatbars-engine.mjs`;
  the spec cannot, so every example in the contract is hand-transcribed rather than
  machine-rendered.
* *Search needs a bolt-on extension*, and the UI comes from a remote `ui-bundle.zip`
  pinned at HEAD rather than from the project's own design system.

A team review weighed three options — stay on Antora, adopt Docusaurus, or adopt
Astro Starlight. Docusaurus was rejected: it is a *third* rendering stack (React)
alongside the existing Astro/Preact, which would fork the shared wordmark and token
layer ([ADR-017](/adr/adr-0017-editor-support-lsp/)) and duplicate the base-path /
Lab-origin machinery the tutorials build already solves. Starlight wins on stack
unity (same Astro family, reuses the design system and the Preact islands), built-in
offline Pagefind search, and a direct path to live engine panes in the spec.

The cost is real and was measured, not assumed: *1,223* `{{` openers (MDX
treats `{{` and `<` as expression/JSX syntax — most sit inside source blocks,
which become MDX-exempt fenced code, leaving a small prose-brace audit), and *353*
`xref:` cross-references whose build-time integrity guarantee must be reconstructed,
since MDX has none natively.

## Decision

Migrate the spec — and only the spec — to Astro Starlight, as follows.

. *Target = Astro Starlight (MDX).* Same stack family as the tutorials; built-in
  offline Pagefind; reuses the design system; avoids a third framework.

. *Standalone app, not folded into `tutorials/`.* The spec ships as its own
  Starlight project under `/spec`, linked to/from the tutorials via the existing
  `PUBLIC_SPEC_BASE` seam — which already separates the two surfaces across several
  pages. Isolating the contract's build keeps a careless tutorial edit from
  red-building the spec's deploy. Shared look-and-feel comes from a factored
  `shared/` module (wordmark, tokens, base-path/Lab helpers), *not* a merged build.

. *Big-bang cutover.* One branch, one reviewable diff, one merge; rollback is a
  revert while `docs/` stays intact until the final step.

. *Versioning snapshots essential releases only.* The `starlight-versions` plugin,
  triggered on tagged spec releases (first `0.1.0`), bounded to avoid folder-snapshot
  bloat. HEAD is "current".

. *All 31 ADRs convert; flat `adr/*.mdx`, status in frontmatter, grouped only in the
  sidebar.* Status changes over an ADR's life; its URL must not, so status never
  enters the path.

. *Route `/spec`, dropping Antora's redundant component segment* (`/flatbars/spec/<page>`,
  not `…/spec/flatbars/<page>`). A redirect map plus a new `check:redirects` gate keep
  old URLs and in-repo `.adoc` links resolving — link stability is gated, not hoped.

. *Build-time guarantees are reconstructed, not dropped.* `starlight-links-validator`
  (build-failing) replaces Antora's `xref` integrity; `astro check` + `astro build`
  replace the AsciiDoc parse gate; a `check:mdx-braces` lint fails on unescaped
  `{{`/`<` outside fences.

. *ADR-031 is recorded "Proposed" first and flipped to "Accepted" only after a
  de-risk spike* proves the three unknowns together: the catalog Markdown emitter, a
  representative page conversion (`concepts`), and one working live engine pane.

## Alternatives considered

*Docusaurus v3* was the other serious MDX candidate and is rejected. Its pitch rests
on three claims that do not survive contact with this project's scope: (1) *stateful
SPA interactivity* for "AST parsing labs" — but the interactive surfaces (`lab/`,
framework-neutral HTML/JS/WASM on its own origin; the Preact islands in `tutorials/`)
are *not* part of the spec and do not migrate, and Astro's islands architecture
ships interactive components fine while emitting zero JS for the prose that dominates
a contract document; (2) *native versioning* — genuinely more mature than Starlight's
`starlight-versions` plugin, but down-weighted because this ADR snapshots essential
releases only (D4), and both use the same folder-snapshot model; and (3)
*future-proofing via Rspack + maintainer backing* — Rspack speeds builds, not the
runtime payload Starlight already wins, and "institutional backing" is symmetric (Astro
is a funded project with a first-party docs product). Decisively, Docusaurus is a
*React* stack — a third frontend framework beside Astro/Preact — which would fork the
design-system single-sources of [ADR-017](/adr/adr-0017-editor-support-lsp/) (tokens,
vocabulary, one wordmark) and duplicate the base-path / Lab-origin machinery the
tutorials build already owns. Stack unity, less shipped JS for a prose spec, and design-system
reuse outweigh Docusaurus's lone real edge in versioning maturity.

## Consequences

* *The codegen single-sources are preserved, not broken.* `FullBars.Catalog` gains a
  `helperCatalogMarkdown` emitter beside the AsciiDoc one (same `preludeSchema`
  source), so `check:catalog` stays a gate on the MDX partial. `gen:tokens` writes the
  shared token CSS once for both sites; `check:adr-nav` and `check:glossary` repoint to
  the MDX sources. The design-system invariants of
  [ADR-017](/adr/adr-0017-editor-support-lsp/) survive intact.

* *Scope is fenced.* The `tutorials/` site is *not* migrated: its 10 pages are
  component-dominant interactive apps (live analyse panes, galleries, JSONata fixers),
  not prose, and stay bespoke `.astro` + Preact. "Starlight everywhere" is rejected —
  format follows content shape. Mermaid diagrams and a broad live-pane rollout are
  out of migration scope (the mechanism is proven once in the spike; rollout is a
  follow-up).

* *A new capability is unlocked:* the spec can render real engine output inline, the
  same way the tutorials do, closing the hand-transcription gap.

* *`CLAUDE.md` is updated as part of the cutover* — its Antora-specific guidance
  (`npm run docs`, the playbook, `supplemental-ui`, the worktree-HEAD caveat) is
  rewritten for the Starlight toolchain.

* *Follow-ups, tracked separately:* unified cross-site Pagefind search; promoting
  `shared/` to a real `@flatbars/design-system` workspace package; the Mermaid
  dialect-ladder diagram; the live-pane content rollout.

*Status:* Accepted. *Date:* 2026-06-01. Records the kernel extraction (commits `c131aaf`, `68b0280`,
`a1c13da`).

## Context

The original `flatbars` package carried *both* the structural core and the engine. The standing
directive was *strict separation of concerns* — "separating later makes it harder, so do it right":
each dialect package contains only its own dialect code, the core is structural only, and the shared
engine is factored into its own package. ADR-001 made the parser/walker split *conceptual*; this ADR
makes it a *package* split.

## Decision

Three tiers plus adapters, dependencies pointing strictly downward.

1. *core (`flatbars`)* — `Lexer`, `Token`, `Parser`, `Syntax`, `Span`, `Error`, `Value`. Meaning-free:
   no engine, no helpers, no validation. `Value` must live at or below core because `Syntax.Expr`
   embeds `Lit Value`; pushing it up would cycle `kernel → core`.

1. *kernel (new package)* — the shared engine: `Engine` (the IoC driver), `Walk`
   (`foldTemplate`/`splitClauses`/`validate`/`Schema`), `Helper` combinators, `ToValue`, `Value`
   (value policy — the named `Truthy` rules / `stringify` / `escapeHtml`), `Env`/`RefEnv`,
   `Prelude`, `Lower`, and `Render` (the `runResolved` glue).

1. *dialects (`rawbars`/`fullbars`/`maxbars`)* — each only its grammar + desugar + render/compile entry
   points, over the kernel, *never each other*. The single sanctioned exception is `maxbars → fullbars`
   (the intentional superset; see [adr-0005-dialect-ladder](/adr/adr-0005-dialect-ladder/)).
*Isolation is an import property, not the ladder's `⊂`.* "No dialect imports another" is about the
package graph; the ladder's `⊂` ([adr-0005-dialect-ladder](/adr/adr-0005-dialect-ladder/)) is about *surface supersetting*
(narrowed by the ADR-005 amendment to surface-superset *modulo documented exceptions* — MaxBars is the
flagship that reuses FullBars's engine wholesale and borrows most, not all, of its surface).
RawBars *has* import isolation (a FullBars-free closure, [adr-0008-rawbars](/adr/adr-0008-rawbars/)); MaxBars
*trades* it for reuse because it genuinely is a FullBars superset. The two properties must not be
conflated — there is exactly *one* sanctioned import crossing.

1. *compile* — `flatbars-compile` is the dialect-agnostic emit driver + `Emit` rules, kept FullBars-free
   (`Compile.Emit` reads `Kernel.Value`); `fullbars-compile` layers the surface compiler on top, so
   RawBars' dependency closure is fully FullBars-free.

1. *adapters* — `json` (JSON ⇆ `Value`, deliberately *out* of core: JSON-ness is a host concern), `js`
   (FFI), `cli`, `playground`.

## Consequences

* *Pro:* the substrate claim is *structural* (enforced by the package graph), not asserted; RawBars'
  closure is provably FullBars-free; a new engine plugs onto `kernel` without touching dialects.
* *Con:* module renames (`FlatBars.Engine → Kernel.Engine`, etc.) rippled to every importer; the
  workspace is now 11 packages; `spago.lock` must be regenerated when a package is added (else test
  deps don't resolve). The "no dialect imports another" rule carries one sanctioned exception.

## Alternatives considered

* *A `common` package.* Rejected: a vague shared bucket with no clear boundary. Extract shared code
  *lazily*, only on a proven second consumer (this is what [adr-0007-minbars](/adr/adr-0007-minbars/) later
  triggers for the truthiness-default parameter and the recursion guard).

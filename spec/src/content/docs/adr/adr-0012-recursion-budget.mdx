*Status:* Accepted — implemented (commit `fdc0b33`). *Date:* 2026-06-01. Required by
[adr-0007-minbars](/adr/adr-0007-minbars/) §4 and the [final review](/adr/adr-final-review/).

## Context

The reference engine's partial helper (`partialH`, `Prelude.purs`) *was* unbounded: a self-including
or mutually-including partial recursed until the stack overflowed. This was a live gap, independent of
any unshipped engine. MinBars (inheritance, dynamic-name partials) made it acute, and any future
recursion construct (self-including partials, labelled loops — [adr-0013-labelled-loops](/adr/adr-0013-labelled-loops/))
needs a defined limit.

## Decision

. *A shared kernel depth/budget*, default **64**, that — when exceeded — raises a *located*
  `RecursionLimit` error rather than crashing the host.
. *It hardens the reference `partialH` immediately*, so the unbounded-recursion gap closes regardless
  of MinBars.
. *Overridable per file* via a header directive (mechanism per [adr-0010-header-directives](/adr/adr-0010-header-directives/);
  spelling — e.g. `@budget` — TBD).
. *Counts render-time re-entry* (partial/block expansion depth), not expression nesting, which is
  already bounded structurally by the parser.

## Implementation

Shipped in commit `fdc0b33`: `RefEnv` carries a `depth` field (0 in `emptyEnv`); `recursionBudget`
is a kernel constant (**64**); `partialH` increments via `enterPartial` on entering a registered
partial and raises `RecursionLimit recursionBudget` once `depth >= budget` — so the reference engine
is bounded (decision items 1, 2, 4). MinBars' `parent`/`partial` reuse the same guard (`f4e98a0`).
The per-file `@budget` *override* (item 3) is not yet implemented — it remains the open question below.

## Consequences

* *Pro:* no unbounded recursion; a single guard serves MinBars, the reference engine, and future
  recursion constructs — a textbook ADR-003 lazy extraction with three consumers.
* *Con:* a global default may be too low for legitimate deep partial trees (hence the override); the
  guard adds a counter to the hot path.

## Open questions

* *Depth-only vs. a work/node budget.* A depth cap is simple but lets a shallow-but-explosive template
  through; a node budget is fairer but harder to explain.
* *The default value* (64 is borrowed from the MinBars decision; no corpus has validated it).
* *The directive spelling* and whether it is engine-wide or per-call.

The core is austere by design. *FlatBars Surface* is an optional dialect that recovers Handlebars
ergonomics. It is *not* a separate parser ([ADR-001](/adr/adr-0001-structural-parser-and-walker/)):
the one structural parser (`parse`) is unchanged, and Surface is a *desugaring walk* over the
structural AST — part of the second pass ([host-api](/engine/host-api/) §7.1), naturally a `foldTemplate`
([A.13.2](/appendix/handlebars/#engine-api)). `FullBars.Surface.desugar` performs the surface
rewrites below (output and paths today; see the status note); it is distinct from
`FullBars.Lower.lower`, which lowers the *core* skeleton to the engine's typed real AST for tooling.
You can run the desugarer, swap it, or write your own.

Surface adds nothing the core cannot already express. Every rule below is a *rewrite* of one
structural node into core nodes. Where a rewrite names a helper (`escapeHtml`, `lookup`, `dict`,
`partial`, …), that helper must exist in the [engine](/engine/prelude/).

:::note
*Implementation status.* `FullBars.Surface.desugar` (and the convenience
`renderSurface` / `compileSurface`) implement §5.1 *output* (`{{ }}` ⇒
escaped, `{{{ }}}` ⇒ raw), §5.2 *paths* (bare, dotted, numeric index,
legacy slash, `this`/`.`, `../`), §5.3 *literals* and head-vs-argument, §5.5
*`@data`* variables (`@index`, `@root.x`, …), and the §5.6 *`else if`* chain. The
reference renderer still runs *core* syntax by default (`renderWith`); call
`renderSurface` to author in the dialect. §5.2 paths include `[bracket]`
segments (`a.[home town]`, `a.[1]` — dots and spaces inside the brackets are
literal). *Partials* (§5.7) work via `renderSurfaceWith`: `{{> name}}`,
`{{> name ctx}}`, dynamic `{{> (expr)}}`, and hash context
`{{> name k=v}}` (the hash merges onto the partial's context) render a
registered partial (unescaped). *Block partials* `{{#partial name}}body{{/partial}}`
render the partial with `body` as the fallback (if missing) and the
`{{> @partial-block}}` yield point; *inline partials*
`{{#*inline "name"}}body{{/inline}}` (the Handlebars decorator form,
with the `*` sigil) define a partial, hoisted into the
registry before rendering. The bare `{{#inline "name"}}` is *rejected*
(`DisallowedShape`): in FullBars, as in Handlebars, `inline` is a decorator, not
a block helper. *Hash arguments* (§5.4) collect into a trailing `dict`:
`{{ f a k=v k2="s"}}` ⇒ `{{{ escapeHtml (f (lookup this "a") (dict "k" … "k2" "s")) }}}`
— this is what feeds `if`/`unless`' `includeZero`, e.g. `{{#if n includeZero=true}}`.
*Block params* (§5.5) work too: `{{#each xs as \|item i\|}}` binds `item`/`i` as scoped
helpers (the index/key), and `{{#with o as \|x\|}}` binds the context — a bare reference to an
in-scope param desugars to a `(param)` call (lexically scoped, visible in nested blocks).

*`@../` parent-data* is desugared for one `../` level: `{{@../index}}`
(and `@../key`/`@../first`/`@../last`) reads the *enclosing* loop's datum via the
`parent-index`/`…` scoped helpers that `each`/`with` install (the data analogue
of `parent` for context). A deeper run (`@../../index`) still resolves to the
immediate parent.

The Handlebars block-partial *sigil* `{{#> name}}…{{/name}}` is also
accepted and desugars to the same core form as the `{{#partial}}`
spelling; the inline-partial *decorator* `{{#*inline "name"}}…{{/inline}}`
is the *required* FullBars author form and desugars internally to the core
`inline` helper. The core lexes `{{#>` and `{{#*` as the distinct
`PartialBlock` and `Decorator` sigils — each with a clean head (the partial name
for `{{#>}}`, the decorator name `inline` for `{{#*inline}}`) and a
`{{/…}}` close that simply repeats that head. They are opt-in via
`ParseOptions.partialBlocks` / `decorators` (on for FullBars; the austere dialects
gate them off as a located `DisallowedShape`). The bare
`{{#inline}}` is rejected by `FullBars.checkBareInline` with a located
`DisallowedShape` error — this gate is FullBars-surface-only (RawBars and MaxBars
still accept bare `{{#inline}}`). See the
[compatibility matrix](/engine/fullbars-compat/) for per-feature status.
:::

:::note[Important]
*Parenthesis convention.* A top-level expression inside `{{{ }}}` needs no grouping — it is
already one `Expr`. Parentheses appear only around a *nested* application in argument position. So
the desugaring of `{{ name }}` is `{{{ escapeHtml (lookup this "name") }}}` — `escapeHtml`
is the top-level operator (no wrapper), and `(lookup this "name")` is parenthesized because it is an
argument.
:::

## 5.1 Output: `{{ }}` and `{{{ }}}`

| Surface | Core |
| --- | --- |
| `{{ E }}` | `{{{ escapeHtml E' }}}` |
| `{{{ E }}}` | `{{{ E' }}}` |

Handlebars' ampersand form `{{& E }}` (unescaped) is accepted as an alias of the triple-stash
`{{{ E }}}` (see §5.6) — both mean "do not escape". The triple-stash is the canonical FullBars
spelling; the austere RawBars and MaxBars dialects accept only it and reject `{{&}}`.

`E'` is `E` after the *path rewrite* (5.2). If `E'` is itself a multi-token application it is wrapped
in parentheses before being handed to `escapeHtml` (it is now an argument): `{{ upcase x }}` →
`{{{ escapeHtml (upcase (lookup this "x")) }}}`.

## 5.2 Paths become `lookup`

| Surface path | Core |
| --- | --- |
| `name` | `(lookup this "name")` |
| `a.b.c` | `(lookup this "a" "b" "c")` |
| `a.1` or `a.[1]` | `(lookup this "a" 1)` |
| `a.[home town]` | `(lookup this "a" "home town")` |
| `a/b` (legacy slash) | `(lookup this "a" "b")` |
| `this` or `.` | `this` |
| `this.a` or `./a` | `(lookup this "a")` |
| `../a` | `(lookup (parent) "a")` |
| `../../a` | `(lookup (parent (parent)) "a")` |
| `@x` | `(x)`  (a scoped data helper — 5.5) |
| `@../x` | `(parent-x)`  (the enclosing loop's datum — 5.5) |

(The right-hand forms are shown parenthesized because in Surface a path almost always lands in
*argument* position — e.g. as the argument of `escapeHtml`. When a path is the whole top-level
expression, e.g. `{{{ name }}}`, the desugaring is the unwrapped `{{{ lookup this "name" }}}`.)

`lookup` is *variadic*: it walks segments left to right, indexing objects by string key and arrays by
number, returning `VNull` at the first miss. `parent` is a scoped helper that block helpers install
to expose the enclosing context (5.5); it replaces Handlebars' implicit context stack with an explicit,
named one.

:::note
A bare path `name` resolves to a *data field* (`lookup this "name"`), never to a helper, because
Surface always wraps it. This is the opposite of the core, where `{{{name}}}` *calls* the
helper `name`. The two layers read the same text differently on purpose: Surface is for authors who
think in data; the core is for the desugarer and the engine.
:::

## 5.3 Helper calls, literals, and subexpressions

Anything that is not a bare path is a helper call, exactly as in the core, with two literal
conveniences:

| Surface | Core |
| --- | --- |
| `true` / `false` / `null` | `(true)` / `(false)` / `(null)` |
| `(helper a b)` | unchanged — grouping is already core |
| `helper a b` (tag head) | unchanged — application is already core |

In *head* position a bare identifier is a helper; in *argument* position a bare identifier that is
not a registered literal is a path. So `{{upcase name}}` →
`{{{ escapeHtml (upcase (lookup this "name")) }}}`.

## 5.4 Hash arguments become a trailing `dict`

| Surface | Core |
| --- | --- |
| `{{helper a k1=v1 k2=v2}}` | `{{{ escapeHtml (helper a (dict "k1" v1 "k2" v2)) }}}` |
| `{{#helper a k=v}}…{{/helper}}` | `{{#helper a (dict "k" v)}}…{{/helper}}` |

All `key=value` pairs collapse into a single `dict` value appended *after* the positional arguments —
the equivalent of Handlebars' `options.hash`.

## 5.5 `@data` and block params become scoped helpers

`each` and `with` install scoped helpers for the duration of their body; Surface `@`-variables are
calls to them, and block params rename them:

| Surface | Core / mechanism |
| --- | --- |
| `@index` `@key` `@first` `@last` | `(index)` `(key)` `(first)` `(last)` — installed by `each` |
| `@../index` `@../key` `@../first` `@../last` | `(parent-index)` … — the *enclosing* loop's datum, installed by `each`/`with` (one `../` level) |
| `@root` | `(root)` — installed by the host at the top frame |
| `{{#each xs as \|item i\|}}` | `{{#each xs "item" "i"}}` — `each` also installs `item` and `i` |
| `{{#with o as \|x\|}}` | `{{#with o "x"}}` — `with` installs `x` alongside the shifted `this` |

Renaming via `as |…|` becomes positional *binding-name* arguments to the block helper.

## 5.6 Branches

`{{else}}` is already core — a separator ([grammar](/spec/grammar/) §2.4) — so Surface passes it
through unchanged. Surface's only job here is the `else if` chain, which it lowers to the engine's
flat `{{elif cond}}` separator (the condition is still path-rewritten):

| Surface | Core |
| --- | --- |
| `{{#if c}}A{{else}}B{{/if}}` | `{{#if c}}A{{else}}B{{/if}}` |
| `{{#each xs}}A{{else}}B{{/each}}` | `{{#each xs}}A{{else}}B{{/each}}` |
| `{{#if a}}A{{else if b}}B{{else}}C{{/if}}` | `{{#if a}}A{{elif (lookup this "b")}}B{{else}}C{{/if}}` |

`else`, `elif`, and `unless` are *engine* names ([prelude](/engine/prelude/) §6.3). A different engine could
read a clause named `otherwise` or provide `case`/`default`; Surface simply targets whatever the
engine defines. (Authoring `{{elif b}}` directly in Surface also works — it is a clause
separator like `{{else}}`.)

FullBars supports Mustache's inverted section `{{^x}}…{{/x}}` (and the triple variant
`{{{^x}}}…{{{/x}}}`), desugaring it to `{{#unless x}}…{{/unless}}` — so "render when
falsy" reads the way Handlebars authors expect. You may always write the `unless` helper explicitly
instead. (The austere RawBars and MaxBars dialects do *not* accept `{{^}}` — there you write
`unless`.) Unescaped output also has the `{{&x}}` alias for `{{{x}}}`.

## 5.7 Partials become `partial` / `inline`

| Surface | Core |
| --- | --- |
| `{{> name}}` | `{{{ partial "name" this }}}` |
| `{{> name ctx}}` | `{{{ partial "name" ctx' }}}` |
| `{{> name k=v}}` | `{{{ partial "name" this (dict "k" v) }}}` |
| `{{> name ctx k=v}}` | `{{{ partial "name" ctx' (dict "k" v) }}}` |
| `{{> (expr)}}` (dynamic) | `{{{ partial (expr) this }}}` |
| `{{#partial name k=v}}body{{/partial}}` | `{{#partial "name" this (dict "k" v)}}body{{/partial}}` |
| `{{> @partial-block}}` | `{{{ partial-block }}}` |
| `{{#*inline "name"}}body{{/inline}}` | `{{#inline "name"}}body{{/inline}}` |

Block partials are written with the *core spelling* `{{#partial}}`
(a bare name is literalized like `{{> name}}`) *or* the equivalent
Handlebars *sigil* `{{#> name}}…{{/name}}`. Inline partials use the
Handlebars *decorator* `{{#*inline "name"}}…{{/inline}}`, which desugars to
the core `inline` helper; the bare `{{#inline …}}` spelling is *rejected*
(`DisallowedShape`) in FullBars — authors do not write `inline` bare. A block `partial`
renders the named partial with its `body` as both the fallback (when the partial is missing) and the
`{{> @partial-block}}` yield point; `inline` definitions are hoisted into the registry before
rendering.

Partials render *unescaped* — a partial produces markup, not a data value, so the desugaring is the
plain triple-stash with no `escapeHtml`. The partial *name* desugars to a `STRING` literal; a dynamic
partial keeps the computed expression. `partial`, `inline`, and the scoped `partial-block` are engine
helpers; see [A.6](/appendix/handlebars/#partials). The scoped `partial-block` is also installed
under the synonym `yield`, the hyphen-free spelling the non-Handlebars dialects use for the same yield
(MaxBars `{{yield}}`, RawBars `{{{yield}}}`; see [maxbars](/engine/maxbars/)).

## 5.8 What Surface does *not* change

Comments, raw blocks, whitespace `~`, and brace-escaping are *core* features and pass through
untouched.

---
title: 1. Lexical structure
---

This chapter defines how a template's bytes are split into *content* and *tags*, and how the pieces
inside a tag are tokenized. The grammar in [grammar](/spec/grammar/) consumes these tokens to build the
skeleton AST. Nothing here knows what any identifier *means*.

## 1.1 Source

A template is a sequence of Unicode characters; the host decodes bytes to text first. The lexer
recognizes a small set of *tag openers* and treats everything else as literal *content*.

## 1.2 Tag openers and the brace count

| Opener | Closer | Meaning |
| --- | --- | --- |
| `{{{` | `}}}` | *Output* — evaluate one expression, write its value. The only inline output form. |
| `{{#` | `}}` … `{{/name}}` | *Block* — a named application that also captures one sub-template (its body). |
| `{{#>` | `}}` … `{{/name}}` | *Partial block* — a `PartialBlock`-sigil block over a clean partial-name head. Opt-in via `ParseOptions.partialBlocks`. |
| `{{#*` | `}}` … `{{/name}}` | *Decorator* — a `Decorator`-sigil block over a clean decorator-name head (e.g. `{{#*inline}}`). Opt-in via `ParseOptions.decorators`. |
| `{{!` | `}}` | *Short comment* — discarded. May not contain `}}`. |
| `{{!--` | `--}}` | *Long comment* — discarded. May contain `}}`, `{{`, and `--`. |
| `{{{{#` | `}}}}` … `{{{{/name}}}}` | *Raw block* — body captured verbatim, never tokenized. |
| `{{` _Ident_ `}}` |  | *Separator* — the bare double-stash `{{ name args }}`. A flat marker; the lexer reads the *shape*, never the name. |

That is the entire opener set. `{{#` is the general block *opener* (`{{#>` and
`{{#*` are its two opt-in specialisations); the bare double-stash
`{{ … }}` is a *separator*, recognized by shape. There is deliberately no:

* `{{^}}` inverse opener — "render when falsy" is the `unless` helper, not a syntax.
* escaped-output `{{ }}` *in the core* — the double-stash is a separator here; escaping is the
  helper `escapeHtml`. The [surface dialect](/engine/surface/) reuses `{{ E }}` for escaped
  output, desugaring it to `{{{ escapeHtml … }}}`; the two layers read it differently.

The separator's identifier — `else`, `elif`, `case`, `default` — is *opaque to the lexer and parser*
([grammar](/spec/grammar/) §2.4). The lexer matches the *longest opener*: `{{{{` before
`{{{` before `{{#*` / `{{#>` before `{{#` before a bare `{{`, and
`{{!--` before `{{!`.

## 1.3 Content and brace escaping

Any run of characters not beginning a tag is *content*, emitted verbatim. A backslash immediately
before a tag opener escapes it: the opener is emitted literally and the backslash is consumed.

```text
\{{{x}}}      emits the literal text {{{x}}}
\{{x}}        emits the literal text {{x}}      (a bare {{ is a separator opener)
\\{{{x}}}     emits a literal backslash, then evaluates {{{x}}}
```

:::note[Important]
*`{{` is significant.* Because the bare double-stash is a separator opener (§1.2), a literal
`{{` in content must be written `{{`. For blocks of text full of braces, a raw block
(`{{{{#raw}}}}…{{{{/raw}}}}`, §1.7) is cleaner. This is a deliberate change from earlier
drafts, where `{{ }}` was not part of the core at all ([ADR-001](/adr/adr-0001-structural-parser-and-walker/)).
:::

## 1.4 Whitespace control: `~`

A tilde immediately inside a tag opener or before a tag closer trims *all* contiguous whitespace on
that side of the tag, including newlines.

```text
{{{~ x ~}}}                    trims around this output
{{~#each xs~}}…{{~/each~}}      trims around the block tags
```

`~` is resolved entirely in the lexer: it adjusts the adjacent content runs and disappears. It never
reaches the AST, so it is not sugar — there is nothing to desugar.

:::note[Important]
FlatBars performs *no implicit "standalone" whitespace removal*. Handlebars.js silently strips the line
around a block/partial/comment that stands alone; FlatBars does not. Whitespace is removed only where
you write `~`. Predictable and explicit; see [A.7](/appendix/handlebars/#comments-raw-ws).
:::

## 1.5 Tokens inside a tag

Within `{{{ … }}}`, `{{# … }}`, and the head of a raw block, the lexer produces:

| Token | Definition | Examples |
| --- | --- | --- |
| `IDENT` | An identifier. One or more characters from `A`–`Z`, `a`–`z`, `0`–`9`, `_`, `-`, `+`, `*`, `?`, `!`, `/`, `.`, `<`, `>`, `=` that does not parse as a `NUMBER`. Must not start with a digit, `-`+digit, `"`, `(`, `)`, or whitespace. | `each`  `escapeHtml`  `partial-block`  `>`  `eq` |
| `STRING` | `"` … `"` or `'` … `'` with escapes `\\` `\"` `\'` `\n` `\t` `\r`. May contain spaces and any tag-like text; the lexer does not look inside strings. | `"home town"`  `'pro'` |
| `NUMBER` | Optional `-`, decimal digits, optional fraction. No exponents in v1. | `3`  `-2.5`  `0` |
| `LPAREN` `RPAREN` | `(` and `)` — grouping. | `(` `)` |
| whitespace | Insignificant inside a tag (significant only via `~`). |  |

The permissive `IDENT` set lets names like `>` (partial), `eq`, `+`, and `partial-block` be
written. `.` is a legal `IDENT` character, so `a.b` lexes as a *single* identifier — the core never
splits it. Dotted *paths* are a surface concept ([surface](/engine/surface/)).

## 1.6 Comments

```text
{{! stripped, no }} allowed inside }}
{{!-- stripped; may contain }} and {{ and -- dashes --}}
```

Both forms are discarded during lexing and never appear in the AST.

## 1.7 Raw blocks

```text
{{{{#raw}}}}
Hello {{name}} — emitted verbatim.
{{{{/raw}}}}
```

After the `}}}}` closing the raw-block head, the lexer captures everything up to the matching
`{{{{/IDENT}}}}` as one uninterpreted string. The closing `IDENT` must equal the opening one.

The quad-stache is the core spelling. In the **statement-tag dialects** (RawBars / MaxBars /
Trussbars — `statementTags`), the literal *verbatim region* is written `{% raw %} … {% endraw %}`
(ADR-039) — it lexes to the same raw-block node (head `raw`), so this section's semantics are
unchanged, and the quad-stache `{{{{#raw}}}}` is rejected there with a fix-it. The distinct
raw-block *helper* form (`{{{{#op}}}}`, head ≠ `raw`, fed to an operation) keeps the quad-stache.

## 1.8 Lexer summary (informative)

```text
CONTENT  --"\\" + opener-->  emit literal opener, stay in CONTENT
CONTENT  --opener-->         switch to matching TAG / RAW / COMMENT state
TAG      --"~"-->            mark trim, continue
TAG      --tokens-->         IDENT | STRING | NUMBER | ( | )
TAG      --closer-->         back to CONTENT (apply pending trims)
RAW      --scan-->           capture verbatim until {{{{/name}}}}
COMMENT  --scan-->           discard until }} (short) or --}} (long)
```
